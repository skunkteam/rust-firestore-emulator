# transaction

## Overview
Transaction registry and concurrency-mode state machines for `FirestoreDatabase`, managing 16-byte rotated transaction tokens, a 6-state `TxnSlot` lifecycle with activity-aware TTL expiration (`60s` unused / `max(120s, last_activity + 60s)` capped at `270s` by default), 4 isolated `4,096`-entry `BoundedRing` tombstone rings, RAII commit slot guards, Cloud-compliant `Rollback`/`ReadOnly`/expiry semantics, and per-mode document/query isolation (`PessimisticState`, `OptimisticState`, `ReadOnlyTransaction`).

## Interface
- `[registry.rs:TransactionId]`: `pub struct TransactionId` — 16-byte little-endian `(lineage_id: u64, attempt_gen: u64)` wire token packing `(instance_id << 32) | local_seq` (`Display` `{lineage_id}:{attempt_gen}`, `TryFrom<&[u8]>`, `TryFrom<Vec<u8>>`, `Into<Vec<u8>>`, `check`, `check_for_instance`, `from_parts`).
- `[registry.rs:ClosedOutcome]`: `pub(crate) enum ClosedOutcome { Committed, AbortedOrRolledBack }` — terminal outcome retained on `Closed` slots for Cloud-compliant rollback and retry behavior.
- `[registry.rs:CommitTake]`: `pub(crate) enum CommitTake { ReadOnly(Arc<ReadOnlyTransaction>), ReadWrite((Arc<ReadWriteTransaction>, CommitSlotGuard)) }` — typed slot handoff returned by `RunningTransactions::take_for_commit`.
- `[registry.rs:CommitSlotGuard]`: `pub(crate) struct CommitSlotGuard` (`finish_committed`, `abort_commit`, `Drop`) — RAII guard owning the `Committing` state of a `ReadWrite` transaction across asynchronous commit execution.
- `[registry.rs:RunningTransactions]`: Synchronous `std::sync::RwLock`-backed transaction registry (`new`, `clear_all`, `reap_if_due`, `reap_and_next_expiry`, `start_read_write`, `start_read_write_with_id`, `start_read_only`, `get_active`, `take_for_commit`, `rollback`) paired with `[registry.rs:tests]` unit, virtual-time, and stress tests.
- `[../transaction.rs:Transaction]`: `pub(crate) enum Transaction { ReadWrite(Arc<ReadWriteTransaction>), ReadOnly(Arc<ReadOnlyTransaction>) }` (`read_doc`, `as_read_write`, `read_time`) re-exporting `TransactionId`, `CommitTake`, and `RunningTransactions`.
- `[../transaction.rs:ReadWriteTransaction]`, `[../transaction.rs:PessimisticState]`, `[../transaction.rs:OptimisticState]`, `[../transaction.rs:ReadOnlyTransaction]`: Concurrency execution state holding `Arc<LockSession>` (`PessimisticState`, `OptimisticState`) or pinned `Timestamp` MVCC read-only snapshots (`ReadOnlyTransaction`), plus queue-free optimistic write-skew validation (`check_concurrency_violations`).

## Invariants
- **6-State `TxnSlot` Machine & 4 Isolated `4,096`-Entry Rings (`[registry.rs:TxnSlot]`, `[registry.rs:BoundedRing]`, `[registry.rs:MAX_RETRY_TOMBSTONES]`, `[registry.rs:MAX_CLOSED_TXNS]`, `[registry.rs:MAX_EXPIRED_TXNS]`)**: Each `lineage_id` maps to `{ current_attempt, slot }` across `Active`, `ReadWrite`-only `Committing`, `Wounded { root_seq, reason, expiry_ns, max_expiry_ns }`, `AbortedLineage { root_seq, max_expiry_ns }`, `Expired { read_only, root_seq, max_expiry_ns }`, and `Closed { outcome, read_only }`. Four isolated `BoundedRing` instances (each capacity `4,096`) bound `retry_ring`, `closed_ring`, `expired_rw_ring`, and `expired_ro_ring` separately so high-volume abandoned `ReadOnly` transactions never evict `Wounded`/`AbortedLineage`, `Closed`, or `Expired` `ReadWrite` tombstones.
- **Activity-Aware TTL, Lock-Order-Safe Reaping & `Committing` Immunity (`[registry.rs:ActiveEntry]`, `[registry.rs:RunningTransactions::reap_and_next_expiry]`, `[registry.rs:RunningTxnMap::refresh_next_expiry]`)**:
  - Unused transactions expire at `created_ns + min(txn_idle, txn_max)` (`60s` default). After the first `get_active` activity under `state.read()`, effective expiry becomes `min(created_ns + txn_max, max(created_ns + txn_used_min, last_activity_ns + txn_idle))` (`max(120s, last_activity + 60s)` capped at `270s` by default).
  - `expiry_heap` (`BinaryHeap<Reverse<ExpiryKey>>`) uses lazy re-heapification on reap, stale-top scrubbing in `refresh_next_expiry()`, and bounded compaction (`retain` when `len > max(2 * active_count, MAX_CLOSED_TXNS)`).
  - Reaping precedence preserves `DatabaseCleared` > `Wounded` > `AbortedLineage` > `Closed` > `Expired`. `TxnSlot::Committing` is removed from `active_count`/`expiry_heap` on `take_for_commit` and is completely immune to idle/max reaping. `LockSession::close_expired()` and `Arc<Transaction>` drops always execute strictly outside `RwLock<RunningTxnMap>`.
- **Cloud-Compliant Expiry, `Rollback` & `ReadOnly` Lifecycle (`[registry.rs:RunningTransactions::rollback]`, `[registry.rs:RunningTransactions::take_for_commit]`, `[registry.rs:RunningTransactions::start_read_write_with_id]`)**:
  - Stale generations (`id.attempt_gen < current_attempt`) return idempotent `Ok(())` on `rollback` even when `current_attempt` is already `Active` or `Committed`.
  - Current-generation `rollback` closes `Active` slots to `Closed { AbortedOrRolledBack }`, leaves in-flight `Committing` commits untouched and returns `Ok(())`, returns idempotent `Ok(())` on `Closed { AbortedOrRolledBack }`, returns idempotent `Ok(())` on `Wounded`/`AbortedLineage`/`Expired` strictly when `now_ns < max_expiry_ns` (preserving tombstones and `root_seq`), and returns `Aborted(EXPIRED_TRANSACTION_MSG)` when `now_ns >= max_expiry_ns` or on `Closed { Committed }`.
  - `Expired` RW/RO slots return `Aborted(EXPIRED_TRANSACTION_MSG)` across `get_active` and `take_for_commit` (for both empty and non-empty writes, preceding `ReadOnly` write rejection); `Wounded` slots transition from their wound `AbortReason` to `Aborted(EXPIRED_TRANSACTION_MSG)` on `get_active`/`take_for_commit` once `now_ns >= expiry_ns`.
  - `take_for_commit(id, has_writes)` on un-expired `Active(ReadOnly)` transitions with `has_writes == true` directly to `Closed { AbortedOrRolledBack, read_only: true }` (`InvalidArgument`), and with `has_writes == false` directly to `Closed { Committed, read_only: true }`.
  - `start_read_write_with_id` rejects `ReadOnly` slots (`Active`, `Expired { read_only: true }`, or `Closed { read_only: true }`) with `InvalidArgument`, rejects un-expired `Active(ReadWrite)` / `Committing` with `FailedPrecondition`, rejects future generations, cross-DB/post-clear tokens (`check_for_instance`), and `u64::MAX` overflows (`checked_add(1)`) with `InvalidArgument`, inherits `root_seq` (`Assigned(seq)`) on `Wounded` / `AbortedLineage` / `Expired { read_only: false }` (even past `max_expiry_ns` or post-`rollback`, closing any un-reaped expired RW session), and rotates `attempt_gen` on valid `Closed { read_only: false }` and same-DB evicted `Entry::Vacant` retries with fresh `LockPriority::Lazy`.
- **Fail-Closed Database Clear & Cancellation Safety (`[registry.rs:CommitSlotGuard]`, `[registry.rs:is_cleared]`)**: `db.is_cleared()` fails closed with `AbortReason::DatabaseCleared` across all entry points (checked inside `state.write()` before inserting slots) and deletes slots immediately (also on `DatabaseDropped`) without retaining `Closed`, `Expired`, or retry tombstones; `take_for_commit` calls `session.mark_commit_started()` while `CommitSlotGuard::drop` closes the `LockSession` and cleans up abandoned `Committing` slots.
- **Queue-Free `OptimisticState` & `ReadOnlyTransaction` Reads (`[../transaction.rs:OptimisticState::read_doc]`, `[../transaction.rs:OptimisticState::check_concurrency_violations]`, `[../transaction.rs:ReadOnlyTransaction::read_doc]`)**: Optimistic reads pin `read_time` before inspecting storage and read MVCC snapshots via `DocumentMeta::read_mvcc_at` without entering `LockTable` queues; optimistic commit validation checks held target `WriteLease`s via `read_with_write_lease` and unheld `observed_docs` / `executed_queries` (`once_for_validation`) queue-free, preserving `CommitError::Aborted` and `GenericDatabaseError::Internal` while mapping query validation failures/mismatches/post-read updates to `AbortReason::OptimisticWriteSkew`.

## Side Effects
- **Instance-Scoped Lineage Counters & Expiry Signals (`[registry.rs:NEXT_INSTANCE_ID]`, `[registry.rs:RunningTransactions::next_local_seq]`, `[registry.rs:RunningTransactions::expiry_notify]`)**: Allocates unique non-zero `instance_id` values (`AtomicU32`) per registry and monotonically increasing `local_seq` values (`AtomicU64`) packed into `lineage_id`, and notifies parked lock waiters via `expiry_notify.notify_waiters()` whenever a newly inserted active transaction lowers `next_expiry_ns`.
- **Lock Session Lifecycle**: Spawns, marks commit-started (`mark_commit_started`), promotes (`Active` -> `Wounded` / `AbortedLineage` / `Expired` / `Closed`), expires (`close_expired` on both pessimistic and optimistic RW sessions), and closes `Arc<LockSession>` handles stored inside `ReadWriteTransaction` variants strictly outside `RwLock<RunningTxnMap>` and without holding locks across `.await`.
