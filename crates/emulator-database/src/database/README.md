# database

## Overview
Core database storage, addressing, Wound-Wait locking, unified commit execution, query, and transaction primitives for `FirestoreDatabase`, including MVCC document versions behind synchronous physical `std::sync::RwLock` guards (`LockableDocument`) gated by capability leases, collection containers, resource references, field paths, projections, structured queries, pipelines, and Wound-Wait pessimistic and optimistic concurrency transactions.

- Subdirectories:
  - [lock](./lock/README.md): Zero-`unsafe` Wound-Wait lock table, session state, priority wait queues, and RAII lease capabilities.
  - [pipeline](./pipeline/README.md): Enterprise Edition `StructuredPipeline` execution engine and expression/function evaluators.
  - [query](./query/README.md): Structured query filter AST, `FindNearest` vector-search specs, and predicate evaluation (`Filter`, `CompositeFilter`, `FieldFilter`, `UnaryFilter`).
  - [transaction](./transaction/README.md): 16-byte rotated `TransactionId` lineage registry, 6-state `TxnSlot` lifecycle, 4 isolated `4,096`-entry rings, and concurrency modes.

## Invariants
- `[document.rs:DocumentMeta::apply_sealed_commit]`, `[document.rs:DocumentContents::maybe_add_version]`, & `[document.rs:stage_stored_version]`: `apply_sealed_commit` locks physical `LockableDocument` write guards in sorted `DocumentRef` order under a `CommitSeal`, stamps a single `commit_time >= lease.acquire_time()` per target lease (returning `GenericDatabaseError::Internal` on clock inversion), `DocumentContents::maybe_add_version` enforces monotonically non-decreasing `update_time` values (`assert!(last.update_time() <= version.update_time())`; updates with identical `update_time` overwrite the latest version in place), and `stage_stored_version` (invoked by `StagedDocument::stage_update`) skips creating a version if `Value::fields_storage_eq` indicates `fields` are unchanged.
- `[commit.rs:FirestoreDatabase::commit_read_write]` & `[lock/table.rs:ReadObservation]`: Upgrading a retained read hold to an exclusive `WriteLease` captures `ReadObservation::{NeverRead, Observed(Option<Timestamp>)}` inside `LockTable`; once the exclusive `WriteLease` is held, `commit_read_write` verifies via `read_with_write_lease` that `last_updated()` still equals the observed timestamp (returning `AbortReason::UpgradeContention` on concurrent modification).
- `[reference.rs:Ref::from_str]` & `[reference.rs:parse_query_ref_root]`: Write resource paths parsed via `Ref::from_str` must match `projects/{project_id}/databases/{database_id}[/documents/...]` where collection/document IDs are non-empty, not `.` or `..`, not matching `is_reserved_name`, and at most 1,500 bytes. Query `ReferenceValue` operands validated via `parse_query_ref_root` share the same segment validation without heap allocation while permitting database roots (`rel_path.is_empty()`) and canonical Datastore `__id<i64>__` odd document segments (rejecting `-0`, leading zeros like `__id01__`, collection/odd-subcollection/collection-`__id...__`/malformed-`__id+1__` paths) across both editions.
- `[field_path.rs:FieldPath::from_str]` & `[field_path.rs:Display]`: Field paths must be non-empty, backtick-quoted segments must wrap entire segments with a matching closing backtick and valid `\` escape sequences, and `Display` is injective (`p1 == p2 <=> p1.to_string() == p2.to_string()`) and roundtrips cleanly through `FromStr`.
- `[validation.rs:ValidatedWrite::parse]`: Enforces 5-step pre-lock write parsing and validation precedence (`operation: None` -> `DocumentRef::from_str` -> database ownership -> `validate_precondition` -> op-specific `Update`/`Delete`/`Transform`), enforces document write constraints on committed field names/values (`validate_writable_value` rejects `None`, `FieldReferenceValue`, `VariableReferenceValue`, `FunctionValue`, `PipelineValue`, nested arrays, invalid `GeoPointValue`, and malformed/oversized/`NaN` `__vector__` sentinel maps), preserves `update_mask: Option<Vec<FieldPath>>` (`Some(vec![])` vs `None`), rejects `Delete` with `update_mask`/`update_transforms`, `Transform` operations (`NotImplemented`), reserved `__.*__` update-mask or transform paths, non-numeric `TransformType::Increment` operands, unspecified/unknown `SetToServerValue` codes, and invalid `Precondition::UpdateTime` timestamp bounds (`seconds >= 0`, `nanos in 0..1_000_000_000`), and pre-validates `Maximum`/`Minimum` operands while deferring `NotImplemented` to `apply_transform` after `check_precondition` (allowing `stage_write` to skip redundant parsing and upfront validation under lock, plus post-merge `validate_writable_fields` when `update_transforms` is empty).
- `[vector.rs:compute_distance]` & `[vector.rs:compute_query_distance]`: Computes unclamped `Euclidean`, `Cosine`, and `DotProduct` distances in direct IEEE 754 `f64`, returning `GenericDatabaseError::FailedPrecondition` on Standard Edition zero-magnitude `Cosine` query/candidate vectors (`GenericDatabaseError::InvalidArgument` on Enterprise Edition and on non-finite `NaN` results).
- `[query.rs:Query::validate]` & `[database.rs:FirestoreDatabase::run_aggregation_query]`: `Query.parent` must be `Ref::Root` or `Ref::Document` (never `Ref::Collection`), `from` must be non-empty, `offset` and `limit` in `Query::from_structured` must be non-negative, and all `order_by` / filter field references and parsed projections must pass `FieldReference::validate_query_reference`. Cross-edition validation rejects empty `CompositeOperator::Or` filters (allowing empty `AND`), requires non-empty `ArrayValue` operands on `IN` / `ARRAY_CONTAINS_ANY` / `NOT_IN`, and validates all `FieldFilter` and `Cursor` operands recursively via `validate_query_operand_value` (rejecting unset `Value` payloads, out-of-range `GeoPointValue`/`TimestampValue`, unsupported `FieldReferenceValue`/`VariableReferenceValue`/`FunctionValue`/`PipelineValue`, malformed `__vector__` sentinel maps—with `NaN` rejected on Enterprise Edition only—and invalid `ReferenceValue` strings via `parse_query_ref_root`). Under Standard Edition (`!enterprise_edition`), filter validation (`validate_standard_filter`) enforces array caps (`IN <= 30`, `ARRAY_CONTAINS_ANY <= 30`, `NOT_IN <= 10`), at most one negation operator (`!=`, `NOT_IN`, `IS_NOT_NAN`, `IS_NOT_NULL`), `NOT_IN` exclusion with `OR` / `IN` / `ARRAY_CONTAINS_ANY`, `__name__` operator, non-empty/non-zero long (`has_zero_datastore_id == false`) and same-root key checks (`validate_standard_key_ref`), and bounded `O(|AST|)` `DnfSummary` limits (`<= 30` disjunctions deduplicated by wire/storage equality with `NaN == NaN` and `<= 1` array-containment per branch), and `order_by` rejects duplicate fields and fields trailing `__name__`; on Enterprise Edition without `find_nearest`, `all_descendants` collection-group queries synthesize implicit `__name__` ordering using the last explicit `order_by` direction (default ascending). When `find_nearest` is absent, cursors are validated *before* implicit `order_by` synthesis (`cursor.values.len() <= self.order_by.len()` and `validate_cursor_key_ref` enforcing `ReferenceValue` + same `(project_id, database_id)` root on explicit `__name__` slots across both editions), missing Standard inequality fields are appended via segment-wise `sorted_non_name_inequality_fields` before optional `__name__` using the last explicit `order_by` direction (default ascending), and cursor comparisons (`doc_on_left_of_cursor`) handle missing fields safely without panicking. When `find_nearest` is set, outer `limit`, `offset > 0`, and cursors are rejected, Standard Edition skips non-finite (`±Infinity`) candidate vectors, excludes implicit `±Infinity` boundary results (`dist < +Infinity` for `Euclidean`/`Cosine`, `dist > -Infinity` for `DotProduct`) when `distance_threshold` is omitted, applies the same Standard `order_by` synthesis (`last_dir`, `__name__`-last check, and `matches_prefilters` field-existence checks) and tie-breaks via `order_by_cmp`, while Enterprise Edition tie-breaks via precomputed `sorted_non_name_inequality_fields` `ASC` then segment-wise `__name__ ASC`. `RunAggregationQuery` `SUM` returns `NULL_VALUE` on empty numeric sets in Enterprise Edition (vs. `0` on Standard Edition); when `enterprise_edition` is enabled, `order_by.is_empty() && find_nearest.is_none()`, and `aggregations` includes `Sum` or `Avg`, `run_aggregation_query` sorts scanned documents by canonical `__name__` for deterministic primary-key scan order (`cmp_firestore_order`) before aggregating, and Enterprise Edition `SUM` / `AVG` accumulate sequentially via `Value::try_checked_sum` in `i64` prior to any `DoubleValue` (failing with `InvalidArgument("Long overflow")` on `(i64, i64)` overflow, vs. Standard Edition `i128` accumulation with final `DoubleValue` promotion).
- `[query.rs:Query::once]`, `[transaction.rs:OptimisticState::check_concurrency_violations]`, & `[../listener.rs:Listener]`: Sorts applicable collections and documents deterministically before acquiring preliminary `ReadLease`s (or performing queue-free `read_mvcc_at` / `read_latest_uncontended` reads) and drops unmatched leases cleanly if mid-scan `NaN`/`FailedPrecondition` errors occur; on success, Standard Edition confirms only top-`K` results, whereas Enterprise Edition (`enterprise_edition == true`) moves all scanned collection document leases before pre-filters so `retain_pessimistic_leases` batch-retains all scanned candidates on `PessimisticTransaction` via `retain_reads` while `OptimisticState::observed_docs` records only returned top-`K` matches and optimistic validation runs queue-free via `once_for_validation`, preserving `CommitError::Aborted` and `GenericDatabaseError::Internal` while mapping query validation failures/mismatches/post-read updates to `AbortReason::OptimisticWriteSkew`. `Listen` (`QueryTarget`) evaluates `find_nearest` during `AddTarget` / `reset` (`Lagged` recovery) and keeps `find_nearest` intact while evaluating subsequent post-catchup updates incrementally per mutated document against `matches_prefilters` (`DocumentChange`, `DocumentRemove`, `DocumentDelete`) without resetting untouched initial matches, emitting multi-document incremental updates deterministically in `cmp_firestore_order` (with a zero-sort fast-path when at most one update matches).
- `[transaction/registry.rs:TransactionId::check_for_instance]` & `[transaction/registry.rs:RunningTransactions]`: Valid 16-byte `(lineage_id, attempt_gen)` wire tokens pack `(instance_id << 32) | local_seq` and require matching `instance_id`, `local_seq` within `1..next_local_seq`, and `attempt_gen >= 1`. `RunningTransactions` tracks 6 `TxnSlot` states (`Active`, `ReadWrite`-only `Committing`, `Wounded`, `AbortedLineage`, `Expired`, `Closed { outcome, read_only }`) with 4 isolated `4,096`-entry bounded rings (`rings: [BoundedRing; 4]` indexed by `RingKind::{Retry, Closed, ExpiredRw, ExpiredRo}`) and activity-aware expiry heaps (`60s` unused, `min(created + 270s, max(created + 120s, last_activity + 60s))` once used, immune once `Committing`). `get_active` / `take_for_commit` return `Aborted(EXPIRED_TRANSACTION_MSG)` on expired slots (preceding RO write rejection) and on `Wounded` slots past `expiry_ns`; `start_read_write_with_id` rejects `ReadOnly` slots with `InvalidArgument`, rejects un-expired `Active(ReadWrite)` / `Committing` / future generations / `u64::MAX` overflow with `FailedPrecondition` or `InvalidArgument`, preserves `root_seq` across `Wounded`/`AbortedLineage`/`Expired` RW retries, and rotates `attempt_gen` on valid retries; `rollback` returns idempotent `Ok(())` on stale generations, `Active` closes, in-flight `Committing`, `Closed { AbortedOrRolledBack }`, and `Wounded`/`AbortedLineage`/`Expired` before `max_expiry_ns` (returning `Aborted(EXPIRED_TRANSACTION_MSG)` at/after `max_expiry_ns` and on `Closed { Committed }`); `DatabaseCleared`/`DatabaseDropped` delete all slots without retaining tombstones. Queue-free read/query paths (`get_doc(Default|ReadTime)`, `Query::once(Default|ReadTime)`) and non-transactional write facades (`apply_single_non_transactional`, `commit_non_transactional`) invoke `reap_if_due()`, while parked pessimistic lock waiters reap pessimistic RW holders via `LockManager`'s `Weak<FirestoreDatabase>` reaper hook (`reap_and_next_pessimistic_expiry()`), releasing locks and dropping expired memory promptly without background tasks.
- `[lock/mod.rs:LockSession]` & `[lock/table.rs:LockTable]`: Coordinates asynchronous `(seq, arrival)` Wound-Wait read/write locking bounded by `Timeouts` (`CLOUD`: 15s write / 16s read; `FAST`: 2s write / 5s read), emitting `tracing::warn!` after 1 second and structured `emulator_database::lock` debug logs (outside `Mutex<LockTable>`), immediately wounding conflicting younger active transactions across documents, waking parked waiters when an older holder's transaction TTL expires, and aborting with `AbortReason` on expiry, timeout, or database clear.
- `[collection.rs:Collection::get_doc]` & `[collection.rs:Collection::peek_doc]`: `get_doc` lazily inserts `Arc<DocumentMeta>` entries into the collection's `RwLock<HashMap<DefaultAtom, Arc<DocumentMeta>>>`; `peek_doc` inspects existing entries without allocating absent document state.
- `[transaction/registry.rs:RunningTransactions]`, `[transaction.rs:PessimisticState]`, `[transaction.rs:OptimisticState]`: Generates instance-scoped `lineage_id` values via `NEXT_INSTANCE_ID` (`AtomicU32`) and per-registry `next_local_seq` (`AtomicU64`), manages active, committing, and four isolated `4,096`-entry bounded rings (`rings: [BoundedRing; 4]` indexed by `RingKind::{Retry, Closed, ExpiredRw, ExpiredRo}`) under synchronous `std::sync::RwLock`, batch-retains pessimistic read holds inside `LockTable`, and records `observed_docs` and `executed_queries` in optimistic `Mutex` state.
