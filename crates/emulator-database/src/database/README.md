# database

## Overview
Core database storage, addressing, query, and transaction primitives for `FirestoreDatabase`, including MVCC document versions with FIFO read/write locking, collection containers, resource references, field paths, projections, structured queries, pipelines, and pessimistic/optimistic concurrency transactions.

## Invariants
- `[document.rs:OwnedDocumentContentsWriteGuard::maybe_add_version]`: Every new version's `update_time` must be `>= self.acquire_time` (otherwise returns `GenericDatabaseError::Internal`) and monotonically non-decreasing (`assert!(last.update_time() <= version.update_time())`); updates with identical `update_time` overwrite the latest version in place, and `maybe_update` skips creating a version if `fields` are unchanged.
- `[document.rs:OwnedDocumentContentsReadGuard::upgrade]`: Upgrading an owned read lock to a write lock verifies that `last_updated()` did not change while waiting; otherwise returns `GenericDatabaseError::Aborted("contention")`.
- `[reference.rs:Ref::from_str]`: Resource paths must match `projects/{project_id}/databases/{database_id}[/documents/...]` where collection/document IDs are non-empty, not `.` or `..`, not matching `is_reserved_name`, and at most 1,500 bytes.
- `[field_path.rs:FieldPath::from_str]`: Field paths must be non-empty, and backtick-quoted segments must wrap entire segments with a matching closing backtick and valid `\` escape sequences.
- `[validation.rs:validate_write]`: Enforces document write constraints on committed field names/values (including strict `__vector__` validation rejecting malformed sentinel maps, `NaN`, or `> 2048` dimensions), rejects reserved `__.*__` update-mask or transform paths, rejects unspecified/unknown `SetToServerValue` codes, and validates `Precondition::UpdateTime` timestamp bounds (`seconds >= 0`, `nanos in 0..1_000_000_000`).
- `[vector.rs:compute_distance]` & `[vector.rs:compute_query_distance]`: Computes unclamped `Euclidean`, `Cosine`, and `DotProduct` distances in direct IEEE 754 `f64`, returning `GenericDatabaseError::FailedPrecondition` on Standard Edition zero-magnitude `Cosine` query/candidate vectors (`GenericDatabaseError::InvalidArgument` on Enterprise Edition and on non-finite `NaN` results).
- `[query.rs:Query::validate]` & `[database.rs:FirestoreDatabase::run_aggregation_query]`: `Query.parent` must be `Ref::Root` or `Ref::Document` (never `Ref::Collection`), and `from` must be non-empty; `FieldFilter` and `Cursor` values validate malformed `__vector__` sentinel maps (`NaN` rejected on Enterprise Edition only). When `find_nearest` is absent, inequality filter fields populate `order_by` if empty in Standard Edition, at most one `ARRAY_CONTAINS` filter is allowed, `__name__` is appended to `order_by` when absent (or when `all_descendants` is enabled), and cursors must not exceed `order_by.len()`. When `find_nearest` is set, outer `limit`, `offset > 0`, and cursors are rejected, Standard Edition skips non-finite (`±Infinity`) candidate vectors and excludes implicit `±Infinity` boundary results (`dist < +Infinity` for `Euclidean`/`Cosine`, `dist > -Infinity` for `DotProduct`) when `distance_threshold` is omitted, equal distances tie-break via `find_nearest_tie_cmp` (on Standard Edition when `order_by` is non-empty: explicit `order_by` then segment-wise `__name__` matching the last `order_by` direction; otherwise across Standard and Enterprise editions: inequality filter fields `ASC` then segment-wise `__name__ ASC`), and `RunAggregationQuery` `SUM` returns `NULL_VALUE` on empty numeric sets in Enterprise Edition (vs. `0` on Standard Edition).
- `[query.rs:Query::once]`, `[transaction.rs:OptimisticState::check_concurrency_violations]`, & `[../listener.rs:Listener]`: Sorts applicable collections and documents deterministically before acquiring read guards and buffers candidate guards locally so mid-scan `NaN`/`FailedPrecondition` errors drop guards cleanly; on success, Standard Edition confirms only top-`K` results, whereas Enterprise Edition (`enterprise_edition == true`) retains all scanned collection guards on `PessimisticTransaction` via `retain_pessimistic_guards` while `OptimisticState::observed_docs` records only returned top-`K` matches and optimistic re-validation maps query errors to `GenericDatabaseError::Aborted`. `Listen` (`QueryTarget`) evaluates `find_nearest` during `AddTarget` / `reset` (`Lagged` recovery) and keeps `find_nearest` intact while evaluating subsequent post-catchup updates incrementally per mutated document against `matches_prefilters` (`DocumentChange`, `DocumentRemove`, `DocumentDelete`) without resetting untouched initial matches.
- `[transaction.rs:TransactionId::check]` & `[transaction.rs:RunningTransactions::start_read_write_with_id]`: Retried transaction IDs must be strictly less than `NEXT_TXN_ID`, must not be `Active` or `Committing`, and must not refer to a `ReadOnly` transaction (`Active`, `Committing`, or retained `Closed`).

## Side Effects
- `[document.rs:lock_timeout]`: Acquires asynchronous FIFO read/write guards (`fifo_rwlock::FifoRwLock`) on `DocumentContents` bounded by `Timeouts` (`CLOUD`: 15s write / 16s read; `FAST`: 2s write / 5s read), logging a `tracing::warn!` after 1 second and aborting with `GenericDatabaseError::Aborted` on timeout.
- `[collection.rs:Collection::get_doc]`: Lazily inserts `Arc<DocumentMeta>` entries into the collection's `RwLock<HashMap<DefaultAtom, Arc<DocumentMeta>>>`.
- `[transaction.rs:RunningTransactions]`, `[transaction.rs:PessimisticState]`, `[transaction.rs:OptimisticState]`: Generates monotonically increasing `TransactionId` values via `NEXT_TXN_ID` (`AtomicUsize`), tracks active, committing, and bounded recently closed (`MAX_CLOSED_TXNS = 4_096`) transactions in `RwLock<RunningTransactionsState>` (supporting idempotent `Rollback` on rolled-back/failed/committing IDs and `Aborted` on committed IDs), retains `OwnedDocumentContentsReadGuard` locks in pessimistic mode, and records `observed_docs` and `executed_queries` in `Mutex` state in optimistic mode.
