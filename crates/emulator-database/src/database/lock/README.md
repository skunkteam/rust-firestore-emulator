# lock

## Overview
Zero-`unsafe` Wound-Wait transaction lock manager for `FirestoreDatabase`, coordinating per-document shared read locks, exclusive write locks, read-to-write upgrades, `(seq, arrival)` priority wait queues, cross-document conflict wounding, and RAII lease capabilities cleanly decoupled from physical document storage.

## Interface
- `[mod.rs:LockPriority]`: `pub(crate) enum LockPriority { Lazy, Assigned(u64), NextSeq }` — selects lazy first-lock priority allocation, inherited retry lineage sequence, or eager monotonic sequence allocation (used for both multi-document non-transactional `WriteBatch` with `can_wound = true, woundable = true` and single-document non-transactional writes / `Default` point reads with `can_wound = false, woundable = false`).
- `[mod.rs:SessionAbortState]`: `pub(crate) enum SessionAbortState { Active, Committing, Wounded(AbortReason), TimedOut(AbortReason), Cleared(AbortReason), Expired(AbortReason), Closed }` — lock-free atomic snapshot of a `LockSession`'s abort/lifecycle state.
- `[mod.rs:LockManager]`: `pub(crate) struct LockManager` (`new`, `set_reaper`, `expiry_notify`, `reap_if_due`, `new_session`, `abort_all`, `is_cleared`) — database-scoped lock coordinator wrapping `Mutex<LockTable>`, monotonic sequence/session counters, and an optional `OnceLock<Weak<FirestoreDatabase>>` TTL reaper hook.
- `[mod.rs:LockSession]`: `pub(crate) struct LockSession` (`root_seq`, `mark_commit_started`, `abort_state`, `check_active`, `check_read_active`, `check_committing_active`, `retain_read`, `retain_reads`, `close`, `close_expired`, `seal_for_commit`, `acquire_read`, `acquire_write`, `acquire_or_upgrade_write`, `acquire_writes_all`) — per-transaction or single-operation lock session handle automatically closing on `Drop`.
- `[leases.rs:ReadLease]`: `pub(crate) struct ReadLease` (`doc_ref`, `check_active`) — non-`Clone` RAII shared read lock capability releasing the active lease hold on `Drop` unless disarmed into a retained hold via `LockSession::retain_read` or `LockSession::retain_reads`.
- `[leases.rs:WriteLease]`: `pub(crate) struct WriteLease` (`doc_ref`, `acquire_time`, `check_active`) — non-`Clone` RAII exclusive write lock capability releasing the write lock on `Drop` unless consumed into a `CommitSeal`.
- `[leases.rs:CommitSeal]`: `pub(crate) struct CommitSeal` (`len`, `get`, `doc_refs`, `check_committing_active`) — non-woundable commit capability holding all exclusive target `WriteLease`s for an atomic `DocumentMeta::apply_sealed_commit` phase and calling `LockSession::close` on `Drop`.
- `[leases.rs:WaiterGuard]`: Internal RAII cancellation guard revoking parked waiters or unconsumed wait promotions when a waiting future drops early.
- `[table.rs:ReadObservation]`: `pub(crate) enum ReadObservation { NeverRead, Observed(Option<Timestamp>) }` — earliest read observation recorded per session on a document for caller-side upgrade contention checking.
- `[table.rs:LockTable]`: Synchronous internal state machine managing per-document readers, writers, `(seq, arrival)` `BTreeMap` wait queues, `PendingWait` outcomes, cross-document `WoundEvent` preemption, `close_expired` stripping (`SessionState::Active` only, surfacing `AbortReason::TransactionExpired` and waking eligible waiters), and retained read holds without holding storage locks or running callbacks.
- `[tests.rs]`: Unit and Tokio virtual-time tests verifying lazy priority assignment, Wound-Wait preemption, non-wounding `NextSeq` single-doc/Default FIFO ordering (`can_wound = false, woundable = false`), upgrade contention observation, multi-document `acquire_writes_all` deadlock immunity, dropped-future revocation, `close_expired` lock release & `Committing` immunity, and timeout/clear semantics.

## Invariants
- **Zero `unsafe` & Zero Storage Callbacks (`[table.rs:LockTable]`, `[../document.rs:LockableDocument]`)**: `LockTable` contains zero `unsafe` code and never touches `DocumentMeta` or invokes closures under `Mutex<LockTable>`. Logical lock acquisition always precedes physical `std::sync::RwLock` borrows, and TTL reaping (`reap_if_due` / `reap_and_next_expiry`) always executes outside `Mutex<LockTable>`, preventing lock-order inversions.
- **Lazy Priority & Strict `(seq, arrival)` Ordering (`[table.rs:LockTable::ensure_session_seq]`, `[table.rs:DocLockState]`)**: `LockPriority::Lazy` allocates a monotonic `seq` inside `LockTable` on a session's first lock acquisition; `LockPriority::Assigned(seq)` preserves a lineage's original `root_seq` across retries; `LockPriority::NextSeq` eagerly allocates the next monotonic `seq` (`can_wound = false, woundable = false` for single-doc non-tx writes and `Default` point reads so later `Lazy` transactions respect arrival order without starvation, and `can_wound = true, woundable = true` for multi-doc `WriteBatch` commits).
- **0ms Cross-Document Wounding & Upgrade Safety (`[table.rs:LockTable::wound_holders_on]`, `[table.rs:LockTable::try_acquire_or_upgrade_write]`)**: An older active requester with `can_wound == true` immediately wounds younger (`rec.seq > requester_seq`) `woundable` active conflicting granted holders across all their held reads, held writes, promoted grants, and parked waiters, then wakes waiters on all affected documents. Blocked `UpgradeWrite` requests release their existing read hold before parking; retained read observations stay strictly inside `LockTable` and are verified by the caller under the acquired `WriteLease` via `DocumentMeta::read_with_write_lease`.
- **Non-Woundable `CommitSeal` (`[mod.rs:LockSession::seal_for_commit]`, `[leases.rs:CommitSeal::drop]`)**: Sealing a commit transitions the session to `SessionState::Committing`, releases any un-upgraded retained read holds, and requires all target `WriteLease`s to belong to the sealing session; dropping `CommitSeal` releases all remaining session locks atomically without individual per-lease relocks.

## Side Effects
- **Bounded Asynchronous Waits, Expiry Wakeups & Slow-Wait Warnings (`[mod.rs:LockSession::await_single_waiter]`, `[mod.rs:LockSession::acquire_writes_all]`, `[mod.rs:LockSession::await_waiter_rx]`)**: `acquire_read`, `acquire_or_upgrade_write`, and `acquire_writes_all` invoke `reap_if_due()` before locking `LockTable`, and blocked waiters race oneshot channels against `Timeouts::read` / `Timeouts::write` (`CLOUD`: 16s / 15s; `FAST`: 5s / 2s), armed `next_expiry < deadline` sleeps, and `expiry_notify` signals (without spawning background tasks), emitting `tracing::warn!` after 1 second under target `emulator_database::lock`, closing timed-out sessions in `LockTable`, and emitting `tracing::debug!` lock/wound telemetry strictly outside `Mutex<LockTable>`.
- **Session Teardown (`[leases.rs:ReadLease::drop]`, `[leases.rs:WriteLease::drop]`, `[leases.rs:CommitSeal::drop]`, `[mod.rs:LockSession::drop]`)**: Automatically release leases, revoke cancelled waiters, and wake queued waiters when dropped.
