# src

## Overview
Root library module for `emulator-database`, implementing `FirestoreProject` multi-database management, `FirestoreDatabase` CRUD/query/aggregation/transaction operations, real-time `Listener` target streams, configuration (`FirestoreConfig`), error mapping (`GenericDatabaseError`), and internal concurrency/validation utilities.

## Interface
- `[lib.rs]`: Re-exports `pub use config::*;`, `pub use database::*;`, `pub use error::GenericDatabaseError;`, `pub use project::FirestoreProject;`, and `pub mod config;`.
- `[config.rs:FirestoreConfig]`: `pub struct FirestoreConfig { pub long_contention_timeout: bool, pub default_enterprise: bool, pub transaction_idle_timeout: Option<Duration>, pub transaction_max_lifetime: Option<Duration> }` (`with_transaction_timeouts`, `with_transaction_idle_timeout`, `with_transaction_max_lifetime`)
- `[project.rs:FirestoreProject]`: `pub struct FirestoreProject` (`new`, `send_project_event`, `subscribe_project_events`, `clear_database`, `database`, `database_names`, `listen`)
- `[database.rs:FirestoreDatabase]`: `pub struct FirestoreDatabase` (`new`, `get_doc`, `peek_doc_meta`, `get_collection_ids`, `get_document_ids`, `run_query`, `run_aggregation_query`, `write`, `create_doc`, `update_doc`, `delete_doc`, `delete_prefix`, `list_docs`, `get_read_time`, `new_txn`, `rollback`, `rollback_sync`, `send_event`, `subscribe`, `enterprise_edition`, `set_enterprise_edition`, `optimistic_concurrency`, `set_optimistic_concurrency`, `set_config`), paired with `[database/commit.rs:FirestoreDatabase::commit]` (unified transactional and non-transactional `commit(writes, Option<TransactionId>)`) and public modules `event`, `field_path`, `pipeline`, `projection`, `query`, `read_consistency`, `reference`.
- `[error.rs:EXPIRED_TRANSACTION_MSG]`, `[error.rs:GenericDatabaseError]`, `[error.rs:AbortReason]`, `[error.rs:CommitError]`: `pub enum GenericDatabaseError { Aborted, AlreadyExists, Cancelled, Internal, InvalidArgument, InvalidReference, FailedPrecondition, NotFound, NotImplemented }` (`grpc_code`, `From<GenericDatabaseError> for tonic::Status`, `From<GenericDatabaseError> for googleapis::google::rpc::Status`), crate-internal `EXPIRED_TRANSACTION_MSG` (`"The referenced transaction has expired or is no longer valid."`) and typed `AbortReason` (`Wounded`, `UpgradeContention`, `ReadTimeout`, `WriteTimeout`, `OptimisticWriteSkew`, `TransactionExpired`, `DatabaseCleared`, `DatabaseDropped`), and `CommitError { Aborted(AbortReason), Other(GenericDatabaseError) }` preserving typed abort causes into `CommitSlotGuard::abort_commit`.
- `[listener.rs:Listener]`: `pub(crate) struct Listener` (`start`)
- `[utils.rs]`: `pub(crate) trait RwLockHashMapExt` (`get_or_insert`) and macros `unimplemented!`, `required_option!`, `unimplemented_option!`, `unimplemented_collection!`, `unimplemented_bool!`.
- Subdirectories:
  - [database](./database/README.md): Core document, collection, reference, field path, projection, query, pipeline, Wound-Wait lock manager ([lock](./database/lock/README.md)), unified commit orchestration (`commit.rs`), read consistency, and transaction lifecycle/registry ([transaction](./database/transaction/README.md)).

## Invariants
- `[database/commit.rs:FirestoreDatabase::commit]` & `[database/transaction/registry.rs:RunningTransactions]`: Request-level write validation (`get_doc_name_from_write`, `ensure_owns_doc`, `validation::validate_write` via `validate_commit_writes`) runs **before** `take_for_commit(id, has_writes)` so validation errors keep both `ReadWrite` and `ReadOnly` transactions `Active`. On `Active(ReadOnly)`, `has_writes == true` transitions to `Closed { outcome: AbortedOrRolledBack, read_only: true }` and returns `InvalidArgument`, whereas `has_writes == false` transitions immediately to `Closed { outcome: Committed, read_only: true }`. On `Active(ReadWrite)`, `take_for_commit` calls `session.mark_commit_started()` and returns an RAII `CommitSlotGuard` holding the `Committing` slot while acquiring sorted target `WriteLease`s (`acquire_or_upgrade_write` / `acquire_write`), verifying pessimistic `ReadObservation` upgrade contention and optimistic `check_concurrency_violations()`, sealing all locks into a `CommitSeal`, and atomically applying mutations inside `DocumentMeta::apply_sealed_commit`. Non-transactional commits (`None`) bypass `RunningTransactions` completely (`target_docs.is_empty()` fast-paths without locks; `target_docs.len() == 1` uses `LockPriority::NextSeq` with `can_wound = false, woundable = false`; multi-document `WriteBatch` acquires all targets concurrently via `acquire_writes_all` with `LockPriority::NextSeq`, `can_wound = true, woundable = true`, and bounded exponential server-side retry on `Wounded`).
- `[database.rs:FirestoreDatabase]`: `new_txn` rejects explicit non-`Unspecified` `TransactionOptions.read_write.concurrency_mode` with `NotImplemented`; `ensure_owns_root` / `ensure_owns_doc` reject mismatched database roots with `InvalidArgument` across database operations; `list_docs` rejects `page_size < 0`, `show_missing && !order_by.trim().is_empty()`, and Enterprise Edition non-empty `order_by` with `InvalidArgument`, rejects `show_missing && collection_id.is_empty()` with `NotImplemented`, parses Standard `order_by` via backtick-and-backslash-aware `parse_list_order_by` (rejecting invalid directions), decodes/validates stateless versioned Protobuf/`base64::URL_SAFE_NO_PAD` `page_token` cursors (`<= 2 MiB`, bound to `(parent, collection_id, show_missing, raw_order_by, mask, effective_orders)` without binding `page_size`/`ReadConsistency`) before `query.once(self)`, applies `start_at` + `limit(page_size + 1)` with unprojected boundary extraction when `!show_missing`, and merges/sorts/filters via `googleapis::cmp_reference_paths` when `show_missing` is `true`.
- `[database.rs:FirestoreDatabase::run_aggregation_query]`: `StructuredQuery.select` must be `None`, and every `Aggregation` must define an `Operator` (`Count`, `Sum`, or `Avg`).
- `[listener.rs:Listener::process_request]`: Listen streams only support `AddTarget` with `target_id == 1` (`TARGET_ID`), a single active target per stream, and a single document in `DocumentsTarget`, enforce cross-database ownership (`InvalidArgument`) on query/document paths and `validate_read_time` on `ResumeType::ReadTime`, and reject `RemoveTarget`, `once`, `expected_count`, `labels`, and `request_options` as unimplemented.

## Side Effects
- `[project.rs:FirestoreProject]`: Lazily allocates and caches `Arc<FirestoreDatabase>` instances in an async `RwLock<HashMap<RootRef, Arc<FirestoreDatabase>>>`, marks cleared databases via `database.mark_cleared()` before dropping them in `clear_database` (immediately closing `DatabaseEvent` subscribers, aborting stale in-flight writes/commits with `Aborted`, and suppressing stale database/config events), and broadcasts lifecycle and mutation `ProjectEvent` notifications over a bounded `tokio::sync::broadcast::Sender<ProjectEvent>` channel (`MAX_PROJECT_EVENT_BACKLOG = 1024`).
- `[database.rs:FirestoreDatabase]`: Validates writable `Value` variants in `[database/validation.rs:validate_write]` and `[database/commit.rs:FirestoreDatabase::stage_write]` (`StagedDocument`), mutates in-memory collection and document state during `write`, `create_doc`, `update_doc`, `delete_doc`, `delete_prefix`, and `commit`, and broadcasts `Arc<DatabaseEvent>` updates via `events: std::sync::Mutex<Option<broadcast::Sender<Arc<DatabaseEvent>>>>` (as well as `ProjectEvent::DocumentsChanged` and `ProjectEvent::DatabaseConfigChanged`) (`MAX_EVENT_BACKLOG = 1024`, suppressing events once `cleared: AtomicBool` is set).
- `[listener.rs:Listener::start]`: Spawns a background `tokio::spawn` task that subscribes to database broadcast streams, emits `ListenResponse` messages over a bounded `mpsc::channel(16)`, exits immediately on `self.sender.closed()`, resets targets on `BroadcastStreamRecvError::Lagged`, and reconnects immediately when `clear_database` calls `mark_cleared()` (or when a database is dropped).
- `[utils.rs:unimplemented]`: Logs unsupported feature messages to `stderr` via `eprintln!`.
