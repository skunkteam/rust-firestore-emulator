# googleapis Source (`src`)

## Overview
Core library implementation for the `googleapis` crate. It includes the `tonic`/`prost`-generated Google Firestore v1 and protobuf well-known types (`tonic::include_proto!("googleapis")`) and extends generated types (`Timestamp`, `TransactionOptions`, `Value`, `Document`, `Precondition`, `StructuredQuery`, `StructuredAggregationQuery`, `AggregationResult`, `RunAggregationQueryRequest`, `RunAggregationQueryResponse`, and `LatLng`) with constructors, accessors, canonical `VectorValue` classification, total ordering, arithmetic aggregations, token serialization, and canonical Proto3 JSON (`serde`) serialization and deserialization.

## Interface
- `[lib.rs:googleapis]`: `tonic::include_proto!("googleapis")` re-exporting generated `google` protobuf modules (`google::firestore::v1`, `google::protobuf`, `google::r#type`, `google::rpc`, `google::api`), including `google::firestore::v1::firestore_client::FirestoreClient` when feature `client` is enabled, plus public module `pub mod vector_ext;` and crate-level re-exports `cmp_reference_paths`, `cmp_reference_segments`, `MIN_TIMESTAMP_SECONDS`, `MAX_TIMESTAMP_SECONDS`, `MAX_VECTOR_DIMENSIONS`, `VECTOR_MAP_TYPE_KEY`, `VECTOR_MAP_TYPE_SENTINEL`, `VECTOR_MAP_VALUE_KEY`, `VectorClassification`, `VectorFormatError`, and `classify_vector_map`.
- `[macros.rs:val]`, `[macros.rs:fields]`, `[macros.rs:doc]`: Hygienic `#[macro_export]` declarative macros building `google::firestore::v1::Value`, `HashMap<String, Value>`, and `Document` instances from JSON-like Rust literals (`null`, scalars, byte slices, nested `[...]` arrays, and `{ "k": v }` maps).
- `[ser/mod.rs]` & `[ser/tests.rs]`: Canonical Proto3 JSON `serde::Serialize` and `serde::Deserialize` implementations (and unit/proptest suite) for `google::protobuf::Timestamp`, `google::r#type::LatLng` (validating `[-90.0, 90.0]`/`[-180.0, 180.0]` bounds with `deny_unknown_fields`), `google::firestore::v1::Value`, `Precondition`, `StructuredQuery` (and nested `Filter`, `CompositeFilter`, `FieldFilter`, `UnaryFilter`, `Order`), `RunQueryRequest`, `RunQueryResponse`, `StructuredAggregationQuery` (and nested `Aggregation`, `Count`, `Sum`, `Avg`), `RunAggregationQueryRequest`, `AggregationResult`, `RunAggregationQueryResponse`, and `ListCollectionIdsRequest`, plus `pub(crate) fn serialize_sorted_map` for deterministic lexicographical key ordering on `Document.fields`, `MapValue.fields`, and `AggregationResult.aggregate_fields` and `pub(crate) fn deserialize_null_default` for Proto3 JSON `null`-as-default fields (alongside `build.rs`-derived `Serialize`/`Deserialize` on `Document`, `DocumentMask`, `ArrayValue`, `MapValue`, `StructuredQuery.CollectionSelector`, `StructuredQuery.FieldReference`, `StructuredQuery.Projection`, `Cursor`, `ListDocumentsResponse`, and `ListCollectionIdsResponse`).
- `[timestamp_ext.rs:MIN_TIMESTAMP_SECONDS]`, `[timestamp_ext.rs:MAX_TIMESTAMP_SECONDS]`: `pub const MIN_TIMESTAMP_SECONDS: i64 = -62_135_596_800` and `pub const MAX_TIMESTAMP_SECONDS: i64 = 253_402_300_799` (Proto3's `0001-01-01T00:00:00Z..=9999-12-31T23:59:59Z` second bounds), re-exported at the crate root in `[lib.rs]` via `pub use timestamp_ext::{MAX_TIMESTAMP_SECONDS, MIN_TIMESTAMP_SECONDS};`.
- `[timestamp_ext.rs:InvalidTokenError]`: `pub struct InvalidTokenError` (implements `std::error::Error` and `From<InvalidTokenError> for String`).
- `[timestamp_ext.rs:TimestampOutOfRangeError]`: `pub struct TimestampOutOfRangeError(Option<time::error::ComponentRange>)` (implements `std::error::Error`, `From<time::error::ComponentRange>`, and `From<TimestampOutOfRangeError> for String`, allowing `Self(None)` for out-of-range `nanos` or out-of-Proto3-bounds `seconds` in `get_token`).
- `[timestamp_ext.rs:Timestamp]`:
  - `pub fn now() -> Timestamp`
  - `pub fn from_token(token: Vec<u8>) -> Result<Self, InvalidTokenError>`
  - `pub fn get_token(self) -> Result<Vec<u8>, TimestampOutOfRangeError>`
  - `pub fn format_utc_compact(self) -> String` (formats UTC `YYYYMMDDTHHMMSSZ` via `time::macros::format_description!`, falling back to `OffsetDateTime::UNIX_EPOCH` when out of `OffsetDateTime` range)
  - Trait implementations: `fmt::Display`, `PartialOrd`, `Ord` (derived via `build.rs`), `From<&OffsetDateTime>`, `From<OffsetDateTime>`, and `TryFrom<Timestamp> for OffsetDateTime`.
- `[transaction_options_ext.rs:TransactionOptions::READ_WRITE]`: `pub const READ_WRITE: TransactionOptions` — default read-write `TransactionOptions` constant with an empty `retry_transaction`.
- `[vector_ext.rs]`:
  - Constants: `VECTOR_MAP_TYPE_KEY`, `VECTOR_MAP_TYPE_SENTINEL`, `VECTOR_MAP_VALUE_KEY`, `MAX_VECTOR_DIMENSIONS`.
  - Types & classifier: `VectorFormatError` (`as_error_message`), `VectorClassification`, `classify_vector_map`.
  - `Value` vector helpers: `vector`, `is_vector`, `as_vector_values`, `iter_vector_f64`.
- `[value_ext.rs:Value]`:
  - Constructors: `reference`, `array`, `map`, `null`, `integer`, `boolean`, `double`, `string`, `timestamp`, `bytes`.
  - Accessors & conversions (total over `value_type: None`, with `as_map` / `as_map_mut` treating valid vectors atomically as `None`): `as_field_reference`, `as_function_value`, `as_reference`, `as_map`, `as_map_mut`, `as_string`, `into_array`, `as_array`, `as_boolean`, `as_double`, `as_integer`.
  - Predicates & wire-storage comparison: `is_nan`, `is_number`, `is_null`, `is_compatible_with`, `storage_eq`, `fields_storage_eq`, `try_checked_sum`.
  - Trait implementations: `PartialEq` (on `Value` and `ValueType`), `Eq` (on `Value` and `ValueType`), `PartialOrd`, `Ord`, `Add`, `Sum`, `Eq`/`PartialOrd`/`Ord` on `Function`, `pipeline::Stage`, and `Pipeline`, plus `From<T> for Value` for `bool`, `i32`, `i64`, `f64`, `&str`, `String`, `bytes::Bytes`, `Vec<u8>`, `&[u8]`, `&[u8; N]`, `[u8; N]`, `Timestamp`, `LatLng`, `Vec<Value>`, `HashMap<String, Value>`, and `Option<T: Into<Value>>`.
- `[value_ext.rs:cmp_reference_segments]`, `[value_ext.rs:cmp_reference_paths]`: Segment-wise Firestore reference ordering normalizing `REFERENCE_NAME_MIN_ID` (`"__id-9223372036854775808__"`) to `""`.
- `[value_ext.rs:LatLng]`: Trait implementations `PartialEq`, `Eq`, `PartialOrd`, and `Ord` using `cmp_f64` on `latitude` then `longitude` (normalizing `-0.0 == +0.0` and ordering all `NaN` bit patterns as equal and less than non-`NaN` floats).

## Invariants
- `[ser/mod.rs:Value]`: Enforces single-key ProtoJSON objects (`nullValue`, `booleanValue`, `integerValue` as decimal string, `doubleValue` with `"NaN"`/`"Infinity"`/`"-Infinity"` support, RFC 3339 `timestampValue`, `stringValue`, padded Base64 `bytesValue`, `referenceValue`, `geoPointValue`, `arrayValue`, `mapValue`, `fieldReferenceValue`, `variableReferenceValue`); rejects bare `null`, null variant payloads (other than `nullValue`), null container elements (`{"fields":{"k":null}}`, `{"values":[null]}`), empty `{}`, or multi-key objects during deserialization so `Value { value_type: None }` is never produced.
- `[ser/mod.rs:serialize_sorted_map]` & `[ser/mod.rs:deserialize_null_default]`: `serialize_sorted_map` serializes `Document.fields`, `MapValue.fields`, and `AggregationResult.aggregate_fields` in deterministic lexicographical key order (placing `"__type__"` before `"value"` in `__vector__` maps) while preserving `-0.0` float serialization; `deserialize_null_default` (alongside `Option<ProtoInt32>` on `RunQueryResponse.skippedResults`, `Option<ProtoInt64>` on `Count.upTo`, and `Option<ProtoDirection>` on `Order.direction`) accepts explicit JSON `null` as the Proto3 default across non-`Option` fields of the 10 `build.rs`-derived types and `*De` request/query containers while accepting decimal strings and integers for `skippedResults` and `Count.upTo`.
- `[ser/mod.rs:Filter]`: Requires `filter_type`, `field`, `op`, `value`, and `operand_type` on deserialized `Filter`, `FieldFilter`, and `UnaryFilter` nodes—as well as non-null `CompositeFilter.op` and `Order.field`—so downstream query compilation never encounters missing required fields.
- `[ser/mod.rs:StructuredQuery]`, `[ser/mod.rs:RunQueryRequest]`, & `[ser/mod.rs:RunAggregationQueryRequest]`: Enforce canonical `camelCase` `deny_unknown_fields`, decode `transaction` via `Option<DecodedBytes>` and encode via `Base64Bytes`, decode unsupported object-typed placeholders (`StructuredQuery.findNearest`, `newTransaction`, `explainOptions`, `requestOptions`) in a single pass via `Option<UnsupportedMessageObject>` (`null` -> `None`, any JSON object `{...}` -> `Some(Default::default())`, non-object values rejected with a serde type error), enforce `oneof consistency_selector` across all three branches (`readTime`, `transaction`, `newTransaction`), and fail serialization when `findNearest`, `NewTransaction`, `explainOptions`, or `requestOptions` are populated.
- `[ser/mod.rs:StructuredAggregationQuery]`, `[ser/mod.rs:Aggregation]`, `[ser/mod.rs:Count]`, `[ser/mod.rs:Sum]`, `[ser/mod.rs:Avg]`: Enforce canonical `camelCase` `deny_unknown_fields`, require exactly one flattened operator (`count`, `sum`, or `avg`) on `Aggregation` (failing serialization when `operator` is `None` and omitting empty `alias`), serialize `Count.upTo` as a quoted decimal string (`None` omitted) and deserialize via `Option<ProtoInt64>` (`i64` bounds, string/integer/`null`) while deferring semantic `< 0` and `Sum`/`Avg` field checks to `emulator-database`.
- `[ser/mod.rs:AggregationResult]` & `[ser/mod.rs:RunAggregationQueryResponse]`: Match `RunQueryResponse` decode semantics without `deny_unknown_fields`, omit empty `aggregateFields` and `transaction` on encode, sort `aggregateFields` lexicographically via `serialize_sorted_map`, and fail serialization when `explainMetrics` is populated.
- `[timestamp_ext.rs:Timestamp::now]` / `[timestamp_ext.rs:next_monotonic]`: Computes `OffsetDateTime::now_utc()` outside `LAST.lock()`, recovers from mutex poisoning via `PoisonError::into_inner`, and guarantees strictly monotonically increasing timestamps with valid `0..1_000_000_000` `nanos` across all calls within the process; if `now <= last` and `last.nanos >= 999_999_999`, rolls over to `Timestamp { seconds: last.seconds + 1, nanos: 0 }` instead of producing `nanos == 1_000_000_000`.
- `[timestamp_ext.rs:TryFrom<Timestamp>]` / `[timestamp_ext.rs:Timestamp::from_token]` / `[timestamp_ext.rs:Timestamp::get_token]` / `[timestamp_ext.rs:Timestamp::format_utc_compact]`: Rejects negative or `>= 1_000_000_000` `nanos` before conversion, encodes tokens as fixed 16-byte big-endian `i128` Unix nanosecond representations constrained to Proto3's `0001..=9999` year bounds (`-62_135_596_800..=253_402_300_799` seconds), and falls back to `OffsetDateTime::UNIX_EPOCH` (`19700101T000000Z`) in `format_utc_compact` for out-of-range timestamps.
- `[vector_ext.rs:classify_vector_map]`: Classifies a `MapValue` as a valid `VectorValue` only when `"__type__"` is `StringValue("__vector__")`, there are no extraneous entries (`len == 2`), `"value"` is an `ArrayValue` of `1..=2048` non-`NaN` `DoubleValue` elements (`-0.0` and `±Infinity` accepted).
- `[value_ext.rs:Value]`: All accessors, predicates, `Ord`, `PartialEq`, `Add`, and `Sum` are total over `value_type: None`; `as_map` and `as_map_mut` return `None` when `self.is_vector()` is `true` so vectors behave atomically across field-path traversal.
- `[value_ext.rs:classify_value_type_rank]` / `[value_ext.rs:Ord]`: Enforce Firestore's canonical value type ordering (`None < Null < Boolean < NaN < Integer/Double < Timestamp < String < Bytes < Reference < GeoPoint < Array < Vector < Map`, with non-document types `FieldReferenceValue`, `VariableReferenceValue`, `FunctionValue`, and `PipelineValue` placed at `u8::MAX - 3..=u8::MAX`), compare valid vectors by `(dimension_len, element_by_element)` with `-0.0 == +0.0`, preserve `(a == b) == (a.cmp(&b) == Ordering::Equal)` alongside `O(K)` zero-allocation regular-map `PartialEq`, and normalize `REFERENCE_NAME_MIN_ID` (`"__id-9223372036854775808__"`) to `""` when comparing `/`-delimited `ReferenceValue` paths and segments.
- `[value_ext.rs:Add]`: Implements Firestore server-side `increment` rules (`i64::saturating_add` for two integers, promotion to `f64` if either operand is a double, and replacement with `rhs` if `self` is non-numeric).
- `[value_ext.rs:Sum]` & `[value_ext.rs:Value::try_checked_sum]`: `Sum` implements Standard Edition `sum`/`avg` rules (skips non-numeric values and `value_type: None`, accumulates integers in `i128` spilling only on `i128` overflow, and single-rounds to `DoubleValue(f64)` on final `i64` overflow), whereas `try_checked_sum` implements Enterprise Edition's sequential `i64::checked_add` rules (returning `Some(Value::integer(0))` when no numeric values are present, and `None` on intermediate or final `(i64, i64)` overflow prior to a `DoubleValue` promotion).

## Side Effects
- `[timestamp_ext.rs:Timestamp::now]`: Samples `OffsetDateTime::now_utc()` outside the lock, then acquires process-global `static LAST: Mutex<Timestamp>` (recovering via `PoisonError::into_inner`) and updates it in place.
