# routes

## Overview
Axum HTTP route modules implementing the Firestore emulator's control plane and SSE live-invalidation stream (`/emulator/v1`), dynamic log capture and polling (`/emulator/v1/logging`), and official Google Cloud Firestore v1 ProtoJSON REST CRUD, query, and database metadata endpoints (`/v1/projects`).

## Interface
- `pub(crate) fn emulator::router() -> Router<&'static FirestoreProject>` (`[emulator.rs:router]`): Mounts `GET /` (`[emulator.rs:list_databases]`), `GET /events` (`[emulator.rs:sse_events]`), `GET`/`DELETE /contention` (`[emulator.rs:get_contention]`, `[emulator.rs:delete_contention]`), `GET /contention/events` (`[emulator.rs:sse_contention_events]`), `GET` (`HEAD`) `/export` (`[emulator.rs:export_snapshot]`), `POST /import` with `DefaultBodyLimit::disable()` (`[emulator.rs:import_snapshot]`) — each with JSON `405 METHOD_NOT_ALLOWED` fallbacks preserving `HEAD` on `GET` endpoints — plus `DELETE /{*ref}` (`[emulator.rs:delete_by_ref]`, `.fallback(unmatched_emulator_route)` returning `404`), and `.fallback(unmatched_emulator_route)` (`[emulator.rs:unmatched_emulator_route]`), compiled regardless of the `ui` Cargo feature.
- `pub(crate) fn logging::router(tracing: &'static impl Tracing) -> Router` (`[logging.rs:router]`), `pub(crate) async fn logging::unmatched_logging_route` (`[logging.rs:unmatched_logging_route]`), and `pub(crate) async fn logging::unmounted_logging_route` (`[logging.rs:unmounted_logging_route]`): Mounts `POST /{name}` (`[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:poll_logs]`) and `DELETE /{name}` (`[logging.rs:stop_capture]`) with a JSON `405 METHOD_NOT_ALLOWED` fallback and JSON `404` unmatched fallbacks backed by `TracingState` (`[logging.rs:TracingState]`), or `501 UNIMPLEMENTED` via `unmounted_logging_route` when dynamic tracing is not configured.
- `pub(crate) fn projects::router() -> Router<&'static FirestoreProject>` (`[projects/mod.rs:router]`): Mounts `GET` and `PATCH /{project_id}/databases/{database_id}` (`[projects/admin.rs:get_database]`, `[projects/admin.rs:patch_database]`), explicit Firestore v1 document/query routes on `/{project_id}/databases/{database_id}/documents`, `:listCollectionIds`, `:runQuery`, `:runAggregationQuery`, and `/{*tail}` delegating to `[projects/documents.rs:dispatch_documents]` with JSON `405 METHOD_NOT_ALLOWED` fallbacks on fixed-method routes, and `.fallback(unmatched_projects_route)` (`[projects/documents.rs:unmatched_projects_route]`).
- `pub(super) fn projects::decode_raw_path_segments(raw_path: &str) -> Result<String>` (`[projects/query_params.rs:decode_raw_path_segments]`) and `pub(super) fn projects::parse_query_pairs(raw_query: &str) -> Result<Vec<(String, String)>>` (`[projects/query_params.rs:parse_query_pairs]`): Shared raw-URI path-segment and query-pair percent-decoders re-exported from `projects/mod.rs` (without re-exporting `percent_decode`, which remains internal to `projects/query_params.rs`); `projects/` uses `parse_query_pairs` (`parse_patch_database_mask`, `DocumentQueryParams::parse`), while `emulator.rs` uses `parse_query_pairs` in `parse_database_query` and `export_snapshot`, and uses only `decode_raw_path_segments` in `delete_by_ref`.
- Submodules under `projects/`:
  - `projects/mod.rs`: Router wiring, `DefaultBodyLimit`, shared root/tail dispatch (`dispatch_root_request`, `dispatch_documents_tail`), raw root-ref/tail/custom-verb parsing helpers (`parse_raw_root_ref`, `parse_root_ref`, `extract_raw_tail`, `split_raw_custom_verb`), and `pub(super)` `decode_raw_path_segments` / `parse_query_pairs` re-exports.
  - `projects/admin.rs`: Database Admin API v1 types (`DatabaseMetadata`, `PatchDatabase` using shared `DatabaseEdition`/`DatabaseConcurrencyMode` and atomic `db.settings()` / `db.update_settings(...)`), `get_database`, `patch_database`, and `parse_patch_database_mask`.
  - `projects/documents.rs`: Unified `dispatch_documents`, all 8 Firestore v1 REST handlers (`handle_get_document`, `handle_list_documents`, `handle_create_document`, `handle_update_document`, `handle_delete_document`, `handle_list_collection_ids`, `handle_run_query`, `handle_run_aggregation_query`), shared query validation helpers (`validate_request_parent`, `ensure_supported_query_options`), `unmatched_projects_route`, and `PHASE2_VERBS`.
  - `projects/query_params.rs`: `DocumentQueryParams` parser/accessors and raw path/query percent-decoding utilities (`decode_raw_path_segments`, `parse_query_pairs`, internal `percent_decode`).

## Invariants
- `GET /emulator/v1` returns `Json(Vec<RootRef>)` (`["projects/{p}/databases/{d}/documents"]`) without creating databases (`[emulator.rs:list_databases]`).
- `GET`/`HEAD /emulator/v1/export` parses repeatable `database=<RootRef>` parameters via `projects::parse_query_pairs` (rejecting unknown keys or empty values with `400 INVALID_ARGUMENT` and validating via `RootRef::from_str`), passes `None` (all databases) or `Some(&targets)` to `FirestoreProject::prepare_export` (returning `404 NOT_FOUND` on unknown databases without lazy instantiation), sets `Content-Type: application/octet-stream` and `Content-Disposition: attachment; filename="..."` built by `default_export_filename` (`<project>-<database>-<utc>.fsemu` sanitized to ASCII `[A-Za-z0-9._-]` with a 200-byte prefix cap when explicit `?database=` targets deduplicate to one database, or `firestore-emulator-snapshot-<utc>.fsemu` otherwise), returns `Body::empty()` immediately on `HEAD` without calling `plan.into_stream()`, and streams `Body::from_stream(plan.into_stream())` on `GET` (`[emulator.rs:export_snapshot]`, `[emulator.rs:default_export_filename]`).
- `POST /emulator/v1/import` disables Axum's default 2 MiB limit via `DefaultBodyLimit::disable()`, rejects any non-empty query string with `400 INVALID_ARGUMENT`, enforces a single `Content-Type: application/octet-stream` header (case-insensitive media type ignoring parameters; rejecting missing, multiple, non-UTF-8, CORS-safelisted, or unknown media types with `415 INVALID_ARGUMENT` including a `curl` hint using `resolve_request_host`), streams `body.into_data_stream()` into `FirestoreProject::import_snapshot`, and returns camelCase `ImportSummaryResponse` / `ImportedDatabaseResponse` JSON (`databases` entries with `name`, `projectId`, `databaseId`, `databaseEdition`, `concurrencyMode`, `documentCount`, `replaced`; plus `totalDatabases`, `totalDocuments`, and optional `importId` omitted on 0-database no-op imports) (`[emulator.rs:import_snapshot]`, `[emulator.rs:ensure_octet_stream_content_type]`, `[emulator.rs:ImportSummaryResponse]`, `[emulator.rs:ImportedDatabaseResponse]`).
- `GET /emulator/v1/contention[?database={rootRef}]` and `DELETE /emulator/v1/contention[?database={rootRef}]` are registered explicitly before `/{*ref}`, work identically with and without the `ui` feature, normalize optional `/documents` via `RootRef::from_str` (returning `400 INVALID_ARGUMENT` on malformed/duplicate/empty `database` or unsupported query parameters), clone database `Arc` handles and drop `project.databases.read().await` before snapshotting or clearing history, never lazily create absent databases (`GET` returns `{"databases":[]}` and `DELETE` returns `{}`), and `DELETE` clears only summary counters and the 256-entry event ring without disturbing active locks or waiters (`[emulator.rs:get_contention]`, `[emulator.rs:delete_contention]`, `[emulator.rs:parse_database_query]`).
- `GET /emulator/v1/contention/events` streams lightweight `ContentionSseEvent` invalidations (`event: contention` with `{"type":"contention_changed"|"database_cleared","database":"..."}`, `event: resync` on >512 broadcast lag) using a `Drop` subscriber guard owned by the SSE stream and 15-second keep-alive heartbeats with zero detached tasks (`[emulator.rs:sse_contention_events]`).
- `DELETE /emulator/v1/{*ref}` decodes raw path segments via `decode_raw_path_segments`, clears an entire database when `{*ref}` is `Ref::Root` (`project.clear_database`), and looks up existing databases via `project.get_existing_database` to recursively delete matching documents and subcollections via `FirestoreDatabase::delete_prefix` when `{*ref}` is `Ref::Collection` or `Ref::Document` (returning a clean `{}` no-op without lazily creating absent databases or emitting `DatabaseCreated`) (`[emulator.rs:delete_by_ref]`).
- `GET /emulator/v1/events` streams `ProjectEvent` notifications (`database_created` with optional `"importId"` when created by import, `database_cleared`, `database_replaced` with `"importId"`, `database_config_changed`, `documents_changed`) as SSE `change` events (and emits `event: resync` if the subscriber lags behind the 1024-event broadcast buffer) with a 15-second keep-alive heartbeat (`[emulator.rs:sse_events]`).
- `GET`/`PATCH /v1/projects/{project_id}/databases/{database_id}` validate root segments via `RootRef::try_new`, format `DatabaseMetadata.name` as `projects/{project_id}/databases/{database_id}` (Admin API v1 format without `/documents`), and read/update `DatabaseEdition` and `DatabaseConcurrencyMode` atomically via `db.settings()` and `db.update_settings(...)`; `PATCH` applies `updateMask` / `update_mask` / `updateMask.paths` / `update_mask.paths` filtering (camelCase & snake_case), derives `optimistic_concurrency` from `database_edition` inside the `update_settings` closure only when the edition changes and concurrency is not explicitly updated, and returns `501 UNIMPLEMENTED` for `firestoreDataAccessMode`, `mongodbCompatibleDataAccessMode`, and `realtimeUpdatesMode` (`[projects/mod.rs:parse_root_ref]`, `[projects/admin.rs:DatabaseMetadata::new]`, `[projects/admin.rs:get_database]`, `[projects/admin.rs:patch_database]`).
- Raw-URI decoding via `decode_raw_path_segments` rejects `%2F`, invalid percent-encoding, and invalid UTF-8 with `400 INVALID_ARGUMENT`, preserves literal `+`, and prevents `%3A` from being split as a `:verb` (`[projects/query_params.rs:decode_raw_path_segments]`, `[projects/documents.rs:dispatch_documents]`).
- `POST` and `PATCH` endpoints in `projects/` require `Content-Type: application/json` via `parse_json_body` / `ApiJson<T>` (`[projects/documents.rs:dispatch_documents]`, `[projects/admin.rs:patch_database]`), extract bodies via `RestBytes` so payloads exceeding `DefaultBodyLimit::max(50 * 1024 * 1024)` (50 MiB, matching `emulator-grpc`) return JSON `413 RESOURCE_EXHAUSTED` envelopes (`[projects/mod.rs:router]`).
- `POST /v1/projects/{p}/databases/{d}/documents/{col}` (`CreateDocument`) requires a non-empty `documentId` query parameter without `/` and an empty `document.name` field, while `UpdateDocument` rejects mismatched non-empty `document.name` values (`[projects/documents.rs:handle_create_document]`, `[projects/documents.rs:handle_update_document]`).
- `GetDocument`, `ListDocuments`, `:runQuery`, and `:runAggregationQuery` support `readTime` consistency (camelCase & snake_case on URL query parameters; strict camelCase JSON in query request bodies) and return `501 UNIMPLEMENTED` for `transaction` or `requestOptions.requestTags` (`:listCollectionIds` returns `501` for `consistency_selector` and implements `pageSize`/`pageToken` pagination); `PHASE2_VERBS` (`[projects/documents.rs:PHASE2_VERBS]`: `commit`, `batchGet`, `batchWrite`, `beginTransaction`, `rollback`, `executePipeline`, `partitionQuery`), `SUBPATH_CUSTOM_VERBS` (`[projects/mod.rs:SUBPATH_CUSTOM_VERBS]`), and `unmatched_projects_route` return `501 UNIMPLEMENTED` for unsupported Phase-2 verbs (`[projects/documents.rs:handle_list_collection_ids]`, `[projects/documents.rs:unmatched_projects_route]`).
- `POST .../documents:runQuery` and root/document-parent `POST .../documents:runAggregationQuery` deserialize once directly into `RunQueryRequest`/`RunAggregationQueryRequest` (enforcing strict `camelCase` `deny_unknown_fields`, `oneof consistency_selector` across `readTime`/`transaction`/`newTransaction`, and object-typed placeholder decoding for `newTransaction`/`explainOptions`/`requestOptions`/`findNearest`, rejecting malformed/non-object/conflicting payloads with `400 INVALID_ARGUMENT`), then enforce `validate_request_parent` and required `structuredQuery` / `structuredAggregationQuery` (`400 INVALID_ARGUMENT`) before rejecting unsupported options (`explainOptions`, `requestOptions`, `findNearest`, `NewTransaction`, `Transaction`) with `501 UNIMPLEMENTED`; `:runQuery` returns a JSON array of `RunQueryResponse` objects padded with a single `{ "readTime": ... }` element when zero documents match, while `:runAggregationQuery` returns a 1-element JSON array `[RunAggregationQueryResponse]` (`[projects/documents.rs:handle_run_query]`, `[projects/documents.rs:handle_run_aggregation_query]`, `[projects/documents.rs:validate_request_parent]`, `[projects/documents.rs:ensure_supported_query_options]`).
- `TracingState` (`[logging.rs:TracingState]`) bounds active capture handles via an LRU `SubscriberStore` (`DEFAULT_MAX_HANDLES = 64`; internal capacity clamped to `>= 1`): opening a handle at capacity evicts the LRU entry, replacing an existing handle refreshes it to MRU without evicting others, `:poll` refreshes recency and retries once on concurrent replacement, and invalid directives return `400 Bad Request` without mutating state (`[logging.rs:SubscriberStore]`, `[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:poll_or_retry_replacement]`).
- Logging locks are acyclic and recover from poisoning via `PoisonError::into_inner`: `SubscriberStore` is a leaf lock (never held across `subscribe`, `drain`, `drop`, or `.await`), `SubscriberHandle` locks only guard `Option<Box<dyn DynamicSubscriber>>` (held across `drain` during `:poll`, released via `take` before teardown), and blocking `Tracing::subscribe` / `Drop` reload calls run outside all locks in a single `tokio::task::spawn_blocking` closure per lifecycle request with `CancelOnDrop` cancellation cleanup (while final `Router` drop tears down remaining active entries synchronously) (`[logging.rs:SubscriberHandle]`, `[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:stop_capture]`).

## Side Effects
- Lazily instantiates missing databases via `project.database(...)` (emitting `ProjectEvent::DatabaseCreated`) on `get_database`, `patch_database`, and `dispatch_documents`, and reads/mutates existing in-memory `FirestoreProject` and `FirestoreDatabase` state across database configuration, snapshot export/import (`prepare_export`, `import_snapshot`), document CRUD, recursive deletion (`emulator.rs:delete_by_ref`), and query execution (`[emulator.rs:export_snapshot]`, `[emulator.rs:import_snapshot]`, `[emulator.rs:delete_by_ref]`, `[projects/admin.rs:get_database]`, `[projects/admin.rs:patch_database]`, `[projects/documents.rs:dispatch_documents]`).
- Subscribes to `FirestoreProject::subscribe_project_events` for long-lived SSE connections (`[emulator.rs:sse_events]`).
- Acquires short-lived `std::sync::Mutex` locks with `PoisonError::into_inner` recovery (`SubscriberStore` and `SubscriberHandle`) to index, poll, and retire log subscribers, offloading `Tracing::subscribe`, final `drain`, and `Drop` teardown onto `tokio::task::spawn_blocking` (`[logging.rs:TracingState]`, `[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:stop_capture]`).
