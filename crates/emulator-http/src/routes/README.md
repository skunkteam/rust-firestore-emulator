# routes

## Overview
Axum HTTP route modules implementing the Firestore emulator's control plane and SSE live-invalidation stream (`/emulator/v1`), dynamic log capture and polling (`/emulator/v1/logging`), and official Google Cloud Firestore v1 ProtoJSON REST CRUD, query, and database metadata endpoints (`/v1/projects`).

## Interface
- `pub(crate) fn emulator::router() -> Router<&'static FirestoreProject>` (`[emulator.rs:router]`): Mounts `GET /` (`[emulator.rs:list_databases]`), `GET /events` (`[emulator.rs:sse_events]`), `DELETE /{*ref}` (`[emulator.rs:delete_by_ref]`), and `.fallback(unmatched_emulator_route)` (`[emulator.rs:unmatched_emulator_route]`).
- `pub(crate) fn logging::router(tracing: &'static impl Tracing) -> Router` (`[logging.rs:router]`): Mounts `POST /{name}` (`[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:poll_logs]`) and `DELETE /{name}` (`[logging.rs:stop_capture]`) backed by `TracingState` (`[logging.rs:TracingState]`).
- `pub(crate) fn projects::router() -> Router<&'static FirestoreProject>` (`[projects.rs:router]`): Mounts `GET` and `PATCH /{project_id}/databases/{database_id}` (`[projects.rs:get_database]`, `[projects.rs:patch_database]`), the unified Firestore v1 document/query dispatcher on `/{project_id}/databases/{database_id}/documents`, `:listCollectionIds`, `:runQuery`, and `/{*tail}` (`[projects.rs:dispatch_documents]`), and `.fallback(unmatched_projects_route)` (`[projects.rs:unmatched_projects_route]`).
- `pub(super) fn projects::decode_raw_path_segments(raw_path: &str) -> Result<String>` (`[projects.rs:decode_raw_path_segments]`): Shared raw-URI path-segment percent-decoder invoked by both `projects.rs` and `emulator.rs:delete_by_ref`.

## Invariants
- `GET /emulator/v1` returns `Json(Vec<RootRef>)` (`["projects/{p}/databases/{d}/documents"]`) without creating databases (`[emulator.rs:list_databases]`).
- `DELETE /emulator/v1/{*ref}` decodes raw path segments via `decode_raw_path_segments`, clears an entire database when `{*ref}` is `Ref::Root` (`project.clear_database`), and recursively deletes matching documents and subcollections via `FirestoreDatabase::delete_prefix` when `{*ref}` is `Ref::Collection` or `Ref::Document` (`[emulator.rs:delete_by_ref]`).
- `GET /emulator/v1/events` streams `ProjectEvent` notifications as SSE `change` events (and emits `event: resync` if the subscriber lags behind the 1024-event broadcast buffer) with a 15-second keep-alive heartbeat (`[emulator.rs:sse_events]`).
- `PATCH /v1/projects/{project_id}/databases/{database_id}` applies `updateMask` / `update_mask` / `updateMask.paths` / `update_mask.paths` filtering (camelCase & snake_case), derives `optimistic_concurrency` from `database_edition` only when the edition changes and concurrency is not explicitly updated, updates edition and concurrency atomically via `db.set_config(...)`, and returns `501 UNIMPLEMENTED` for `firestoreDataAccessMode`, `mongodbCompatibleDataAccessMode`, and `realtimeUpdatesMode` (`[projects.rs:patch_database]`).
- Raw-URI decoding via `decode_raw_path_segments` rejects `%2F`, invalid percent-encoding, and invalid UTF-8 with `400 INVALID_ARGUMENT`, preserves literal `+`, and prevents `%3A` from being split as a `:verb` (`[projects.rs:decode_raw_path_segments]`, `[projects.rs:dispatch_documents]`).
- `POST` and `PATCH` endpoints in `projects.rs` require `Content-Type: application/json` via `parse_json_body` / `ApiJson<T>` (`[projects.rs:dispatch_documents]`, `[projects.rs:patch_database]`), and `projects::router()` configures `DefaultBodyLimit::max(50 * 1024 * 1024)` (50 MiB, matching `emulator-grpc`) so large multi-vector payloads are accepted (`[projects.rs:router]`).
- `POST /v1/projects/{p}/databases/{d}/documents/{col}` (`CreateDocument`) requires a non-empty `documentId` query parameter without `/` and an empty `document.name` field, while `UpdateDocument` rejects mismatched non-empty `document.name` values (`[projects.rs:handle_create_document]`, `[projects.rs:handle_update_document]`).
- `GetDocument`, `ListDocuments`, and `:runQuery` support `readTime` consistency (camelCase & snake_case) and return `501 UNIMPLEMENTED` for `transaction` or `requestOptions.requestTags` (`:listCollectionIds` returns `501` for `consistency_selector` and implements `pageSize`/`pageToken` pagination); `PHASE2_VERBS`, `SUBPATH_CUSTOM_VERBS`, and `unmatched_projects_route` return `501 UNIMPLEMENTED` for unsupported Phase-2 verbs (`[projects.rs:handle_list_collection_ids]`, `[projects.rs:unmatched_projects_route]`).
- `POST .../documents:runQuery` returns `501 Not Implemented` when `structuredQuery.findNearest` (or `structured_query.find_nearest`) is a JSON object (`400 Bad Request` for other non-null values), and otherwise returns a JSON array of `RunQueryResponse` objects, padded with a single `{ "readTime": ... }` element when zero documents match (`[projects.rs:handle_run_query]`).
- `TracingState` (`[logging.rs:TracingState]`) bounds active dynamic log capture handles via an LRU `SubscriberStore` capped at `DEFAULT_MAX_HANDLES = 64` (configurable via `router_with_max_handles`, clamped to `>= 1`): inserting a new handle evicts the least-recently-used entry when at capacity, replacing an existing handle refreshes it to MRU without evicting others, `:poll` refreshes handle recency (and retries once on a concurrent replacement), and invalid directives return `400 Bad Request` without mutating or evicting existing handles (`[logging.rs:SubscriberStore]`, `[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:poll_logs]`).
- Logging lock ordering is strictly acyclic with non-poisoning mutex recovery (`PoisonError::into_inner`): the short-lived `SubscriberStore` map lock is a leaf lock (never held across `subscribe`, `drain`, `drop`, or `.await`), per-handle `SubscriberHandle` locks only guard `Option<Box<dyn DynamicSubscriber>>` (and inner `SharedBuffer` during `drain`), and blocking `tracing` reload calls (`Tracing::subscribe` and `Drop` of replaced, evicted, or stopped subscribers) run outside all map and per-handle locks on `tokio::task::spawn_blocking` (`[logging.rs:SubscriberHandle]`, `[logging.rs:drain_and_drop_handles]`, `[logging.rs:stop_capture]`).

## Side Effects
- Lazily instantiates missing databases via `project.database(...)` (emitting `ProjectEvent::DatabaseCreated`) on `get_database`, `patch_database`, and `dispatch_documents`, and reads/mutates in-memory `FirestoreProject` and `FirestoreDatabase` state across database configuration, document CRUD, recursive deletion, and query execution (`[emulator.rs:delete_by_ref]`, `[projects.rs:get_database]`, `[projects.rs:patch_database]`, `[projects.rs:dispatch_documents]`).
- Subscribes to `FirestoreProject::subscribe_project_events` for long-lived SSE connections (`[emulator.rs:sse_events]`).
- Acquires short-lived non-poisoning mutexes (`Arc<Mutex<SubscriberStore>>` and per-handle `SubscriberHandle` locks) to index, poll, and retire dynamic log subscribers, offloading `Tracing::subscribe` and `DynamicSubscriber` teardown onto Tokio's blocking thread pool (`[logging.rs:TracingState]`, `[logging.rs:start_capture_or_poll_logs]`, `[logging.rs:stop_capture]`).
