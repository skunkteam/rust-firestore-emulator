# Conformance Test Suites (`test-suite/tests`)

## Overview

End-to-end `@google-cloud/firestore` Node.js SDK conformance test suites verifying that `firestore-emulator` matches live Google Cloud Firestore behavior across document CRUD, field transforms, structured/aggregation/collection-group/descendant queries, pessimistic and optimistic transactions, MVCC snapshot `readTime` isolation, real-time document and query listeners, and Enterprise Edition pipeline execution. Every suite runs unchanged against live Cloud Firestore (`npm test`) as the authoritative ground truth, against the Rust emulator (`just sdk-test` / `npm run test:rust-emulator`), and against Google's Java-based Firebase emulator (`npm run test:java-emulator`).

## Interface

- `[1-get-set.test.ts]`: Parameterized across `editions` (`describe.each(editions)`). Verifies `doc.get()`, `firestore.getAll()`, `doc.set()` (overwrite and `{ merge: true }`), `doc.create()`, `doc.update()` (including multi-byte UTF-8 nested `FieldPath` updates), `doc.delete()`, concurrent opposite-order `WriteBatch` deadlock-freedom, `FieldValue` transforms (`serverTimestamp`, `delete`, `increment`, `arrayUnion`, `arrayRemove`), and UTF-8 / 1,500-byte / path / `__.*__` document key constraints (`notImplementedInJava` guards the 1,500-byte check).
- `[2-basic-query.test.ts]`: Parameterized across `editions` on both direct collections and `collectionGroup('subCollection')`. Verifies canonical cross-type `orderBy` ordering, range and inequality filters (`<`, `<=`, `>`, `>=`, `!=`, `==`, `in`, `not-in`, `array-contains`, `array-contains-any`, plus `Filter.or` + inequality and canonical lexicographical multi-inequality `orderBy`), `FieldPath` escaping, cursor pagination (`limit`, `offset`, `startAt`, `startAfter`, `endAt`, `endBefore`), `select` projections, historical `readTime` queries, `listDocuments()` (including phantom ancestor discovery, boundary doc deletion/mutation, `mask`, `orderBy`, `showMissing`, and `pageToken` validation via raw GAPIC calls) and `listCollections()`, `count()` / `sum()` / `average()` aggregations, and `i64`/`f64`/`BigInt`/`-0.0`/`NaN`/`GeoPoint` comparison edge cases.
- `[3-pessimistic-transaction.test.ts]`: Parameterized over `editions.filter(e => e.concurrencyMode === 'pessimistic')`. Verifies transactional read-before-write rules, atomic multi-write composition, abort rollback, pessimistic per-document locking (existing and non-existing docs), non-transactional `set`/`update`/`WriteBatch` waiting on transaction locks, FIFO write-starvation prevention (`read waiting on write-lock that is waiting on a read-lock`), deterministic Wound-Wait deadlock breaking across both `ref1 < ref2` and `ref2 < ref1`, Standard Edition (`!fs.enterprise`) query-level locks (including secondary-transaction query contention), and Commit 1 Cloud Wound-Wait validation Probes A–D (`probe A1`..`probe D4`) using `ConcurrentTest` and raw unary/stream gRPC calls (`notImplementedInJava` guards 6 lock/query tests; zero `notImplementedInRust` guards remain).
- `[4-live-docs.test.ts]`: Parameterized across `editions`. Verifies `DocumentReference.onSnapshot` initial/incremental snapshots, unsubscribe cleanup, 450 concurrent document listeners, suppression of duplicate snapshots on no-op writes (`set`/`update` with identical fields, `-0`, or `NaN`), snapshot emission when storage representation changes (`-0.0` double to `0` int), and single consolidated emission for multi-transform transactions.
- `[5-live-queries.test.ts]`: Parameterized across `editions` and 4 query shapes (`full collection`, `==`, `!=`, `>=`), plus `array-contains-any` and `not-in` `.limit(3)` live query transitions. Verifies `Query.onSnapshot` initial and incremental snapshots, subcollection isolation, consolidated `WriteBatch` emissions, in-place updates, deletions, and dynamic `.orderBy('ordered').limit(3)` window membership.
- `[6-readonly-transaction.test.ts]`: Parameterized across `editions`. Verifies `runTransaction(..., { readOnly: true, readTime? })` monotonic `serverTimestamp` vs. `writeTime` ordering, client-side write rejection in read-only transactions, `ConcurrentTest` snapshot isolation without explicit `readTime`, `3 INVALID_ARGUMENT` rejection of future/negative `readTime`, MVCC point-in-time `getAll` snapshots across historical `writeTime`s, and `{ fieldMask }` projections.
- `[7-descendants-query.test.ts]`: Parameterized across `editions`. Verifies `allDescendants` queries rooted at either a `CollectionReference` or a (potentially phantom) `DocumentReference`, with and without `collectionId` restriction, across 18 operations (`get`, `aggregate`, `count`, `endAt`, `explain`, `limit`, `limitToLast`, `offset`, `onSnapshot`, `orderBy`, `select`, `startAfter`, `startAt`, `where`, `withConverter`), branching expected error codes via `connection` and `fs.enterprise`.
- `[8-optimistic-transaction.test.ts]`: Parameterized over `optimisticDatabases = editions.filter(e => e.concurrencyMode === 'optimistic')` (falling back to `describe.skip.each(editions)` on Java emulator). Uses `ConcurrentTest` to verify lock-free concurrent reads, absence of deadlocks on opposite-order reads, snapshot `readTime` pinning on the first `txn.get(docRef)` or `txn.get(query)`, write-skew retry on concurrent document or query-range mutations (including `offset(1).limit(1)` when a skipped leading document is deleted concurrently), and zero retries for no-write read-write transactions.
- `[9-pipeline-operators.test.ts]`: Parameterized over `enterpriseDatabases = editions.filter(e => e.enterprise)` (skipped on Standard Edition and Java emulator). Verifies Enterprise Edition `@google-cloud/firestore/pipelines` stages (`collection`, `where`, `limit`, `offset`, `sort`, `select`, `addFields`, `removeFields`, `distinct`, `aggregate` with `groups`, `findNearest` across `euclidean`/`cosine`/`dot_product`, snapshot `executionTime` consistency (populated, empty/filtered-to-empty, `readOnly` transactions, and concurrent writes), `expectCloudLimitationCanary` threshold checks, raw `executePipeline` wire rejections, IEEE 754 vector extreme/overshoot/infinity cases, and multi-frame `> 4 MiB` streaming, plus `notImplementedInRust`-guarded `collectionGroup`, `database`, `documents`, `createFrom`, `replaceWith`, `sample`, `union`, `unnest`), vector distance/length expressions (`cosineDistance`, `euclideanDistance`, `dotProduct`, `vectorLength`, `isError()`, and `null` propagation), expression semantics (`int64` truncating vs. `float64` division, `null`/missing propagation, `isError` suppression, and `notImplementedInRust`-guarded `ifError`), and compile-time exhaustive `Record<..., ...>` coverage across all exported pipeline methods, functions, logic operators, search operators, and aggregate accumulators.
- `[10-rust-oracle-edge-cases.test.ts]`: Parameterized across `editions`. Verifies ground-truth Cloud Firestore gRPC status codes for `exists` and `lastUpdateTime` write preconditions on missing and mismatched documents (`update` and `delete`), atomic failed multi-write batches, and transaction commit/rollback lifecycle semantics (idempotent `Rollback` after rollback/failed commits/optimistic `ABORTED`/concurrent blocked `Commit`, `10 ABORTED` on `Rollback` after succeeded `Commit`, `3 INVALID_ARGUMENT` on malformed tokens, preservation of active RW/RO transactions on commit request validation errors, and closing + non-retryability of RO transactions on rejected write commits).
- `[11-vector-search.test.ts]`: Parameterized across `editions` using shared raw-RPC helpers from `./utils` (`notImplementedInJava` guards 8 assertions/blocks including sections 10 and 12). Verifies end-to-end vector storage (`1D`..`2048D`, `-0.0`, `±Infinity`, vectors in arrays, `"____"`, atomic subpath overwrite), canonical cross-type/intra-type `orderBy`, `EUCLIDEAN`/`COSINE`/`DOT_PRODUCT` `findNearest` + `distanceThreshold`, composite pre-filters (including `array-contains-any` and Enterprise `not-in`) + secondary distance tie-breaking (explicit `orderBy` `'asc'` on both Standard and Enterprise plus `'desc'` on Enterprise, repeated single-field inequality tie-breaking on Standard vs. unordered equal-distance ties on Enterprise), Standard `findNearest` `> 30` DNF and `NOT_IN + OR` rejections, `select()` shadowing/masking + `RunAggregationQuery`, real-time `Listen` initial `findNearest` snapshot + incremental base-query updates, `ConcurrentTest` edition-aware transactional lock scope + `NewTransaction` rollback, isolated `collectionGroup` segment-wise tie-breaking, SDK/wire domain validation (edition-aware `code === 9` vs. `code === 3` on zero-norm `COSINE`, and Enterprise `raw-nan-2d`), and `expectCloudLimitationCanary` checks (`limit`/`offset`/cursors).
- `[12-structured-query-validation.test.ts]`: Parameterized across `editions` with zero new Cloud composite indexes. Verifies `array-contains-any` and `not-in` execution across scalar/nested-array/map/`BigInt` types, the full Standard vs. Enterprise `null`/`NaN`/missing-field matrix (via SDK and raw `ARRAY_CONTAINS`/`EQUAL`/`NOT_EQUAL`/`LESS_THAN`/`LESS_THAN_OR_EQUAL`), 5,000-element Enterprise arrays, aggregations (`count`/`sum`/`average`), pessimistic/optimistic transactional locking and write-skew retries, and (guarded by `notImplementedInJava`) the server-side `rawRunQuery` validation matrix (wire subfields, unset `Value`s, empty `OR` vs. `AND`, array bounds/caps, DNF 30-disjunction & negation limits, `__name__` / `__id<i64>__` / `docsRoot` / reserved `FieldPath` checks across `filter`/`unary`/`order`/`select`/`getDocument`, duplicate/`__name__`-last `order_by` rules, and pre-synthesis / cross-db cursor checks).
- `[13-transaction-ttl.test.ts]`: Parameterized across `editions` (`60s`/`120s`/`270s` on live Cloud; `10s`/`20s`/`30s` via `FIRESTORE_EMULATOR_TRANSACTION_IDLE_TIMEOUT_MS` and `FIRESTORE_EMULATOR_TRANSACTION_MAX_LIFETIME_MS` under `just sdk-test`). Verifies idle TTL expiration for unused RW/RO and used RW transactions across `getDocument`, `batchGetDocuments`, `runQuery`, empty/non-empty `commit`, idempotent pre-max-lifetime `rollback`, expired RW vs. RO `retryTransaction` semantics, lineage priority inheritance for retried expired transactions, `runTransaction` automatic retry on expiry, pessimistic lock release for parked and arriving writers, activity-based idle TTL refresh past the used baseline, and (when `FIRESTORE_EMULATOR_TRANSACTION_MAX_LIFETIME_MS` is configured on Rust emulator) max-lifetime cap enforcement (`10 ABORTED` on RPCs and post-max `rollback`, plus rotated `retryTransaction`).
- Subdirectories:
    - `utils`: [./utils/README.md](./utils/README.md) - Backend connection detection (`CLOUD FIRESTORE` / `RUST EMULATOR` / `JAVA EMULATOR`), edition fixtures, `ttl` document wrappers, `expectCloudLimitationCanary`, raw GAPIC RPC helpers, and `ConcurrentTest` synchronization helpers.

## Invariants

- **Cloud Firestore Ground Truth (`[./utils/firestore.ts:connection]`)**: Every assertion in `*.test.ts` must hold against live Google Cloud Firestore (`connection === 'CLOUD FIRESTORE'`); emulator-specific unimplemented features are gated explicitly with `notImplementedInRust || ...` or `notImplementedInJava || ...` rather than weakening assertions.
- **Edition & Concurrency Coverage (`[./utils/firestore.ts:editions]`, `[2-basic-query.test.ts:fs.enterprise]`)**: Suites parameterized over `editions` validate Standard Edition pessimistic semantics (implicit document-ID and inequality-field ordering, `!=` excluding `null`/missing fields, query locking) alongside Enterprise Edition optimistic and pessimistic semantics (unordered default scans, `!=` including `null`/missing fields, pipeline execution).
- **Pipeline SDK Exhaustiveness (`[9-pipeline-operators.test.ts:describe('Exhaustive API Type Checks')]`)**: TypeScript `Record<RelevantExpressionMethods, ...>`, `Record<RelevantExportedFunctions, ...>`, `Record<LogicOperators, ...>`, `Record<SearchOperators, ...>`, and `satisfies Record<AggregateOperators, unknown>` enforce at compile time that every `@google-cloud/firestore/pipelines` operator is explicitly tested or guarded by `notImplementedInRust`.
- **Feature & Bugfix Conformance Rule**: Adding support for an unimplemented Firestore capability requires removing its `notImplementedInRust` guard (or adding new conformance cases in `1-*.test.ts`..`13-*.test.ts`) and verifying against both Cloud Firestore (`npm test`) and the Rust emulator (`just sdk-test`); fixing any behavioral bug requires a reproducing conformance test in this directory.

## Side Effects

- **Live gRPC & HTTP Mutations (`[1-get-set.test.ts]`..`[13-transaction-ttl.test.ts]`, `[./utils/firestore.ts]`)**: Creates, updates, queries, streams (`onSnapshot`), and recursively deletes isolated test collections under project `firestore-test-406503` across `(default)`, `enterprise`, and `enterprise-pessimistic` databases on the active backend (live GCP Cloud Firestore, local Rust emulator on `127.0.0.1:8080`, or Firebase Java emulator).
- **Real-Time Timers & Concurrency (`[3-pessimistic-transaction.test.ts]`, `[4-live-docs.test.ts]`, `[5-live-queries.test.ts]`, `[6-readonly-transaction.test.ts]`, `[7-descendants-query.test.ts]`, `[8-optimistic-transaction.test.ts]`, `[9-pipeline-operators.test.ts]`, `[10-rust-oracle-edge-cases.test.ts]`, `[11-vector-search.test.ts]`, `[12-structured-query-validation.test.ts]`, `[13-transaction-ttl.test.ts]`)**: Opens up to 450 concurrent gRPC `Listen` streams in `[4-live-docs.test.ts]` and real-time `onSnapshot` / `RawVectorListener` streams in `[5-live-queries.test.ts]`, `[7-descendants-query.test.ts]`, and `[11-vector-search.test.ts]`, schedules wall-clock `timers/promises` delays and `ConcurrentTest` synchronization barriers in `[3-pessimistic-transaction.test.ts]` (up to `40_000` ms), `[6-readonly-transaction.test.ts]`, `[8-optimistic-transaction.test.ts]`, `[10-rust-oracle-edge-cases.test.ts]`, `[11-vector-search.test.ts]` (`25_000` ms `ConcurrentTest`), `[12-structured-query-validation.test.ts]`, and `[13-transaction-ttl.test.ts]`, and extends Jest test timeouts to `30_000` ms in `[9-pipeline-operators.test.ts]` and `[11-vector-search.test.ts]` and `Math.max(120_000, ...)` in `[13-transaction-ttl.test.ts]`.
