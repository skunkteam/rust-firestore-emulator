# Conformance Test Suites (`test-suite/tests`)

## Overview
End-to-end `@google-cloud/firestore` Node.js SDK conformance test suites verifying that `firestore-emulator` matches live Google Cloud Firestore behavior across document CRUD, field transforms, structured/aggregation/collection-group/descendant queries, pessimistic and optimistic transactions, MVCC snapshot `readTime` isolation, real-time document and query listeners, and Enterprise Edition pipeline execution. Every suite runs unchanged against live Cloud Firestore (`npm test`) as the authoritative ground truth, against the Rust emulator (`just sdk-test` / `npm run test:rust-emulator`), and against Google's Java-based Firebase emulator (`npm run test:java-emulator`).

## Interface
- `[1-get-set.test.ts]`: Parameterized across `editions` (`describe.each(editions)`). Verifies `doc.get()`, `firestore.getAll()`, `doc.set()` (overwrite and `{ merge: true }`), `doc.create()`, `doc.update()`, `doc.delete()`, `FieldValue` transforms (`serverTimestamp`, `delete`, `increment`, `arrayUnion`, `arrayRemove`), and UTF-8 / 1,500-byte / path / `__.*__` document key constraints (`notImplementedInJava` guards the 1,500-byte check).
- `[2-basic-query.test.ts]`: Parameterized across `editions` on both direct collections and `collectionGroup('subCollection')`. Verifies canonical cross-type `orderBy` ordering, range and inequality filters (`<`, `<=`, `>`, `>=`, `!=`, `==`, `in`, `array-contains`, `array-contains-any`), `FieldPath` escaping, cursor pagination (`limit`, `offset`, `startAt`, `startAfter`, `endAt`, `endBefore`), `select` projections, historical `readTime` queries, `listDocuments()` (including phantom ancestor discovery) and `listCollections()`, `count()` / `sum()` / `average()` aggregations, and `i64`/`f64`/`BigInt`/`-0.0`/`NaN`/`GeoPoint` comparison edge cases.
- `[3-pessimistic-transaction.test.ts]`: Parameterized over `editions.filter(e => e.concurrencyMode === 'pessimistic')`. Verifies transactional read-before-write rules, atomic multi-write composition, abort rollback, pessimistic per-document locking (existing and non-existing docs), non-transactional `set`/`update`/`WriteBatch` waiting on transaction locks, FIFO write-starvation prevention (`read waiting on write-lock that is waiting on a read-lock`), deadlock breaking, and Standard Edition (`!fs.enterprise`) query-level locks using `ConcurrentTest` (`notImplementedInJava` guards 6 lock/query tests; `notImplementedInRust` guards 1 secondary-transaction query lock case).
- `[4-live-docs.test.ts]`: Parameterized across `editions`. Verifies `DocumentReference.onSnapshot` initial/incremental snapshots, unsubscribe cleanup, 450 concurrent document listeners, suppression of duplicate snapshots on no-op writes (`set`/`update` with identical fields, `-0`, or `NaN`), snapshot emission when storage representation changes (`-0.0` double to `0` int or `1.0` double to `1` int), and single consolidated emission for multi-transform transactions.
- `[5-live-queries.test.ts]`: Parameterized across `editions` and 4 query shapes (`full collection`, `==`, `!=`, `>=`). Verifies `Query.onSnapshot` initial and incremental snapshots, subcollection isolation, consolidated `WriteBatch` emissions, and dynamic `.orderBy('ordered').limit(3)` window membership.
- `[6-readonly-transaction.test.ts]`: Parameterized across `editions`. Verifies `runTransaction(..., { readOnly: true, readTime? })` monotonic `serverTimestamp` vs. `writeTime` ordering, client-side write rejection in read-only transactions, MVCC point-in-time `getAll` snapshots across historical `writeTime`s, and `{ fieldMask }` projections.
- `[7-descendants-query.test.ts]`: Parameterized across `editions`. Verifies `allDescendants` queries rooted at either a `CollectionReference` or a (potentially phantom) `DocumentReference`, with and without `collectionId` restriction, across 18 operations (`get`, `aggregate`, `count`, `endAt`, `explain`, `limit`, `limitToLast`, `offset`, `onSnapshot`, `orderBy`, `select`, `startAfter`, `startAt`, `where`, `withConverter`), branching expected error codes via `connection` and `fs.enterprise`.
- `[8-optimistic-transaction.test.ts]`: Parameterized over `optimisticDatabases = editions.filter(e => e.concurrencyMode === 'optimistic')` (falling back to `describe.skip.each(editions)` on Java emulator). Uses `ConcurrentTest` to verify lock-free concurrent reads, absence of deadlocks on opposite-order reads, snapshot `readTime` pinning on the first `txn.get(docRef)` or `txn.get(query)`, write-skew retry on concurrent document or query-range mutations, and zero retries for read-only transactions.
- `[9-pipeline-operators.test.ts]`: Parameterized over `enterpriseDatabases = editions.filter(e => e.enterprise)` (skipped on Standard Edition and Java emulator). Verifies Enterprise Edition `@google-cloud/firestore/pipelines` stages (`collection`, `where`, `limit`, `offset`, `sort`, `select`, `addFields`, `removeFields`, `distinct`, `aggregate` with `groups`, plus `notImplementedInRust`-guarded `collectionGroup`, `database`, `documents`, `createFrom`, `replaceWith`, `sample`, `union`, `unnest`), expression semantics (`int64` truncating vs. `float64` division, `null`/missing propagation, `isError`/`ifError` suppression), and compile-time exhaustive `Record<..., ...>` coverage across all exported pipeline methods, functions, logic operators, search operators, and aggregate accumulators.
- Subdirectories:
  - `utils`: [./utils/README.md](./utils/README.md) - Backend connection detection (`CLOUD FIRESTORE` / `RUST EMULATOR` / `JAVA EMULATOR`), edition fixtures, `ttl` document wrappers, and `ConcurrentTest` synchronization helpers.

## Invariants
- **Cloud Firestore Ground Truth (`[./utils/firestore.ts:connection]`)**: Every assertion in `*.test.ts` must hold against live Google Cloud Firestore (`connection === 'CLOUD FIRESTORE'`); emulator-specific unimplemented features are gated explicitly with `notImplementedInRust || ...` or `notImplementedInJava || ...` rather than weakening assertions.
- **Edition & Concurrency Coverage (`[./utils/firestore.ts:editions]`, `[2-basic-query.test.ts:fs.enterprise]`)**: Suites parameterized over `editions` validate Standard Edition pessimistic semantics (implicit document-ID and inequality-field ordering, `!=` excluding `null`/missing fields, query locking) alongside Enterprise Edition optimistic and pessimistic semantics (unordered default scans, `!=` including `null`/missing fields, pipeline execution).
- **Pipeline SDK Exhaustiveness (`[9-pipeline-operators.test.ts:describe('Exhaustive API Type Checks')]`)**: TypeScript `Record<RelevantExpressionMethods, ...>`, `Record<RelevantExportedFunctions, ...>`, `Record<LogicOperators, ...>`, `Record<SearchOperators, ...>`, and `satisfies Record<AggregateOperators, unknown>` enforce at compile time that every `@google-cloud/firestore/pipelines` operator is explicitly tested or guarded by `notImplementedInRust`.
- **Feature & Bugfix Conformance Rule**: Adding support for an unimplemented Firestore capability requires removing its `notImplementedInRust` guard (or adding new conformance cases in `1-*.test.ts`..`9-*.test.ts`) and verifying against both Cloud Firestore (`npm test`) and the Rust emulator (`just sdk-test`); fixing any behavioral bug requires a reproducing conformance test in this directory.

## Side Effects
- **Live gRPC & HTTP Mutations (`[1-get-set.test.ts]`..`[9-pipeline-operators.test.ts]`, `[./utils/firestore.ts]`)**: Creates, updates, queries, streams (`onSnapshot`), and recursively deletes isolated test collections under project `firestore-test-406503` across `(default)`, `enterprise`, and `enterprise-pessimistic` databases on the active backend (live GCP Cloud Firestore, local Rust emulator on `127.0.0.1:8080`, or Firebase Java emulator).
- **Real-Time Timers & Concurrency (`[3-pessimistic-transaction.test.ts]`, `[4-live-docs.test.ts]`, `[5-live-queries.test.ts]`, `[8-optimistic-transaction.test.ts]`)**: Opens up to 450 concurrent gRPC `Listen` streams in `[4-live-docs.test.ts]` and schedules wall-clock `timers/promises` delays and `ConcurrentTest` synchronization barriers (up to `40_000` ms in `[3-pessimistic-transaction.test.ts:locks]`).

## Verification
- Run (from repository root, builds Rust binary + runs suite): `just sdk-test`
- Run (inside `test-suite/`, against live Google Cloud Firestore): `npm test`
- Run (inside `test-suite/`, against pre-built Rust binary — no build step): `npm run test:rust-emulator`
- Run (inside `test-suite/`, against Google Java emulator): `npm run test:java-emulator`
- Run (inside `test-suite/`, lint & format check): `npm run lint`
