# UI Components (`ui/components`)

## Overview
Stateless `lit-html` view templates and session/controller helpers powering the primary workspaces and dialogs of the Firestore Emulator Web UI: horizontal Miller-column collection/document exploration (`explorer.js`), hybrid structured field-tree and Raw ProtoJSON document editing (`editor.js`), interactive `StructuredQuery` building and execution (`query.js`), and database/document/collection modals (`modals.js`).

## Interface
- `[explorer.js:renderExplorer]`: Renders arbitrary-depth horizontal Miller columns (`Root Collections` -> `Documents` -> `Document Inspector & Subcollections` -> nested levels), including phantom ancestor document indicators (`showMissing=true`), collection filters, pagination (`Load more`), and collection/document action triggers.
- `[editor.js:createEditorSession]` / `[editor.js:syncSessionWithDocument]` / `[editor.js:fieldsToDraftNodes]` / `[editor.js:draftNodesToFields]` / `[editor.js:extractSessionFields]` / `[editor.js:computeChangedFieldMask]` / `[editor.js:renderHybridEditor]`: Manages bidirectional conversion and validation between recursive `DraftNode` trees and Raw ProtoJSON `{"fields": ...}` text, computes `updateMask.fieldPaths` diffs (including deleted fields), and renders both the Structured Tree View and Raw ProtoJSON editor tabs.
- `[query.js:createQueryRunnerState]` / `[query.js:buildStructuredQueryFromVisual]` / `[query.js:renderQueryRunner]`: Manages visual filter rows across all 14 operators (`EQUAL`, `NOT_EQUAL`, `LESS_THAN`, `LESS_THAN_OR_EQUAL`, `GREATER_THAN`, `GREATER_THAN_OR_EQUAL`, `ARRAY_CONTAINS`, `IN`, `ARRAY_CONTAINS_ANY`, `NOT_IN`, `IS_NULL`, `IS_NOT_NULL`, `IS_NAN`, `IS_NOT_NAN`), `AND`/`OR` `compositeOp`, optional `parentSubpath` scoping, `orderBy` clauses, `allDescendants` collection-group scope, `limit`, synced Raw `StructuredQuery` JSON, and clickable query result cards (`.query-result-card` with `Open in Explorer ›` buttons).
- `[modals.js:renderModal]`: Renders active modal dialogs (`open_db`, `create_doc`, `delete_doc`, `delete_col`, `clear_db`) and handles modal form validation, calling `../api.js`, `../state.js`, and `../router.js` directly while delegating database selection, path hydration, list refresh, toast notifications, and re-rendering via `ModalCallbacks`.

## Invariants
- `[editor.js:renderHybridEditor]`: Inside the inner `switchMode` handler, switching from Raw ProtoJSON mode back to Structured Tree mode re-validates `validateRawProtoJsonFields(session.rawText)` so invalid JSON text cannot corrupt the structured `DraftNode` tree, and switching from Structured to Raw is blocked when `draftNodesToFields` fails.
- `[editor.js:valueToDraftNode]` / `[editor.js:renderDraftNode]`: `__vector__` sentinel maps (verified via `[../values.js:isVectorMapValue]`) render as collapsed read-only `'vector'` rows (`vec` badge + `[../values.js:formatVectorSummary]` + remove `✕` button, without a type dropdown or nested tree) and pass their untouched `rawVectorValue` from `cleanDoc` through verbatim on save (preserving untouched `-0.0` coordinates and dirty state across Structured <-> Raw ProtoJSON mode switches via `cleanJson` / `rawBaselineText`).
- `[editor.js:computeChangedFieldMask]` / `[editor.js:recomputeDirty]`: In structured mode, diffs `cleanDoc.fields` against draft fields structurally via `[../values.js:firestoreValueEquals]` rather than `JSON.stringify` (avoiding false positives from map key ordering or `-0` normalization while keeping untouched vector fields out of `updateMask`); in raw mode, checks `session.rawText.trim() !== session.cleanJson.trim()`.
- `[editor.js:collectMapNodes]`: Sibling field keys inside any `Document.fields` or `mapValue.fields` object must be non-empty and unique before saving or syncing to ProtoJSON (invoked via `draftNodesToFields`).
- `[query.js:FILTER_OPERATORS]`: All 14 `StructuredQuery` operators supported by `crates/emulator-database/src/database/query/filter.rs` are exposed in the visual query builder, with `IN`, `ARRAY_CONTAINS_ANY`, and `NOT_IN` sharing the `kind: "array"` editor mode. Visual array parsing runs `[../values.js:findUnsafeUnquotedInteger]` before `JSON.parse`, validates explicit ProtoJSON entries via `[../values.js:normalizeProtoValue]` (requiring string `"Infinity"`/`"-Infinity"`/`"NaN"` on explicit `doubleValue` objects and passing `inArray = f.op === "ARRAY_CONTAINS_ANY"` so `ARRAY_CONTAINS_ANY` disallows nested `arrayValue` objects while `IN`/`NOT_IN` permit single-level `arrayValue` objects), encodes non-`-0` `Number.isSafeInteger` shorthand items as `integerValue` strings, encodes `-0`, fractional numbers, and unsafe-integer floats as numeric `doubleValue`s, rejects overflowing shorthand numeric literals (`Infinity`/`-Infinity`), and rejects nested JS arrays (`Array.isArray(item)`).

## Side Effects
- `explorer.js`, `editor.js`, and `query.js`: Pure DOM template construction and in-memory `EditorSession` / `QueryRunnerState` mutation; network I/O is delegated upward to callbacks in `[../app.js]`.
- `modals.js`: Mutates `state.modal` / `state.segments` / `state.rootCollections` / `state.databases`, bumps/updates epochs, request sequences, and caches directly via `[../state.js]` (`bumpDbEpoch`, `bumpNavEpoch`, `deleteDocumentLevelCache`, `pruneCachesWithPrefix`, `clearActiveDatabaseState`), calls Firestore/Emulator APIs directly via `[../api.js]`, updates history directly via `[../router.js:syncBrowserUrl]`, and delegates database selection/hydration/list refresh/toast/rendering to `ModalCallbacks` in `[../app.js]`.
