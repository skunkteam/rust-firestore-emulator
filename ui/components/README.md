# UI Components (`ui/components`)

## Overview
Stateless `lit-html` view templates and session/controller helpers powering the primary workspaces and dialogs of the Firestore Emulator Web UI: horizontal Miller-column collection/document exploration (`explorer.js`), hybrid structured field-tree and Raw ProtoJSON document editing (`editor.js`), interactive 2x2 (`Documents`/`Aggregations` × `Visual`/`Raw JSON`) `StructuredQuery` & `StructuredAggregationQuery` building and execution (`query.js`), reusable pure `lit-html` WAI-ARIA 1.2 combobox rendering (`combobox.js`), DB-scoped standard-REST discovery and field-sampling autosuggestions (`query-suggestions.js`), live Wound-Wait lock contention visualization (`contention.js`), and database/document/collection modals (`modals.js`).

## Interface
- `[explorer.js:renderExplorer]`: Renders arbitrary-depth horizontal Miller columns (`Root Collections` -> `Documents` -> `Document Inspector & Subcollections` -> nested levels), including phantom ancestor document indicators (`showMissing=true`), collection filters, pagination (`Load more`), and collection/document action triggers.
- `[editor.js:createEditorSession]` / `[editor.js:syncSessionWithDocument]` / `[editor.js:fieldsToDraftNodes]` / `[editor.js:draftNodesToFields]` / `[editor.js:extractSessionFields]` / `[editor.js:computeChangedFieldMask]` / `[editor.js:renderHybridEditor]`: Manages bidirectional conversion and validation between recursive `DraftNode` trees and Raw ProtoJSON `{"fields": ...}` text, computes `updateMask.fieldPaths` diffs (including deleted fields), and renders both the Structured Tree View and Raw ProtoJSON editor tabs.
- `[query.js:createQueryRunnerState]` / `[query.js:createFilterRow]` / `[query.js:buildStructuredQueryFromVisual]` / `[query.js:buildAggregationQueryFromVisual]` / `[query.js:renderQueryRunner]`: Manages 2x2 (`Documents`/`Aggregations` × `Visual`/`Raw JSON`) Query Runner state (`QueryFilterRow` with `valueTypeManuallySet`/`valueUserEdited`, `QueryOrderRow`, `QueryAggregationRow`, `limitUserModified`, independent `rawQueryText` / `rawAggregationText` buffers, and separate Document vs. Aggregation result/read-time/timing/provenance slots), visual filter rows across all 14 operators (`EQUAL`, `NOT_EQUAL`, `LESS_THAN`, `LESS_THAN_OR_EQUAL`, `GREATER_THAN`, `GREATER_THAN_OR_EQUAL`, `ARRAY_CONTAINS`, `IN`, `ARRAY_CONTAINS_ANY`, `NOT_IN`, `IS_NULL`, `IS_NOT_NULL`, `IS_NAN`, `IS_NOT_NAN`), non-clobbering filter auto-type detection (`applyFilterAutoType`), `AND`/`OR` `compositeOp`, optional `parentSubpath` scoping, `orderBy` clauses, `allDescendants` collection-group scope, edition-aware `COUNT`/`SUM`/`AVG` aggregation rows (Standard `1..=5` vs. Enterprise `1..=64` via optional `{ enterprise }` / `enterprise` prop defaulting to `false`), `limit` (`min="0"`), optional `suggestions?: QuerySuggestionStore` wiring (`renderCombobox` across `parentSubpath` with `keepOpenOnSelect` on `col/`, `Collection ID`, `Where`, `Order By`, and `SUM`/`AVG`, reconciling `comboboxUi` against visible visual combobox IDs via `reconcileComboboxUi` and falling back to plain `<input>` controls when `suggestions` is omitted), clickable Document result cards (`.query-result-card` with `Open in Explorer ›` buttons), and lossless typed Aggregation result cards (`.agg-result-card` with `.type-badge` labels and `.agg-provenance-note` constraint hints).
- `[combobox.js:createComboboxUiState]` / `[combobox.js:closeActiveCombobox]` / `[combobox.js:reconcileComboboxUi]` / `[combobox.js:renderCombobox]`: Pure `lit-html` WAI-ARIA 1.2 combobox (`ComboboxUiState`, `ComboboxItem`, `ComboboxRect`, `RectLike`, `ElementLike`) with zero `HTMLElement` / `customElements` references and per-member DOM guards, supporting case-insensitive filtering over `value`/`label`/`matchText`, strict `<ul role="listbox">` -> `<li role="option">` lists with sibling `.combobox-empty` (`"Loading..."` vs. `"No matching suggestions"`) and `.combobox-footer` + `.combobox-refresh-btn` (`tabindex="-1"`), `flipUp` viewport positioning (`availableBelow < 280 && availableAbove > availableBelow`), `mousedown` `preventDefault()` + `@blur` active-ID guard, dynamic `keepOpenOnSelect`, keyboard navigation (`ArrowDown`/`ArrowUp`/`Home`/`End`/`Enter`/`Escape`/`Tab`), and capture-phase `scroll` + `resize` clip-bounds dismissal (`#topbar`, `.query-builder-pane`, viewport, detached anchor).
- `[query-suggestions.js:formatSuggestionFooter]` / `[query-suggestions.js:createQuerySuggestionStore]` / `[query-suggestions.js:resetQuerySuggestionStore]` / `[query-suggestions.js:markSuggestionsStale]` / `[query-suggestions.js:ensureSubcollections]` / `[query-suggestions.js:ensureParentSubpathSuggestions]` / `[query-suggestions.js:ensureCollectionGroups]` / `[query-suggestions.js:ensureFieldSuggestions]`: DB-scoped standard-REST autosuggestion store (`SuggestionContext`, `SuggestionCacheEntry`, `FieldHint`, `FieldScopeEntry`, `QuerySuggestionStore`) managing 4 single-owner caches (`subcollectionsByParent`, `docIdsByCollection`, `collectionGroupsByParent`, `fieldsByScope`), internal store `epoch`, and keyed `AbortController` deduplication/`force`-abort lifecycle: root `Collection ID` uses `ctx.rootCollections` synchronously, even-segment `parentSubpath` fetches `:listCollectionIds`, slash-triggered `parentSubpath` alternates `listDocuments?showMissing=true&mask.fieldPaths=__name__&pageSize=100` and `:listCollectionIds`, `allDescendants` runs a single key-only `:runQuery` (`limit: 500`) seeded uniformly with direct child collections, and lazy unfiltered field sampling (`limit: 25`) traverses maps up to depth `5` (`200` paths, `32` array items, stopping at `isVectorMapValue`, skipping `isReservedName`, escaping via `escapeFieldPathSegment`, pinning `__name__` last in `items` and excluding it from `aggItems`, prioritizing numeric fields in `aggItems`, and populating `fieldHints`).
- `[contention.js:createContentionState]` / `[contention.js:formatWaitDuration]` / `[contention.js:getDisplayedContentionDatabases]` / `[contention.js:hasContentionWaiters]` / `[contention.js:updateWaiterElapsedDom]` / `[contention.js:renderContention]`: Renders the Contention Visualizer workspace (`woundsTotal`, `timeoutsTotal`, `upgradeAbortsTotal`, `writeBatchRetriesTotal`, scope selector + `Clear history`, truncation banners, active writers/readers/ordered waiter queues with empty `.wait-elapsed[data-wait-base-ms][data-wait-ms][data-wait-label]` anchors, recent events feed with wounder attribution, and clickable document links) plus DOM-only waiter elapsed duration updates.
- `[modals.js:renderModal]` / `[modals.js:handleModalKeydown]` / `[modals.js:getModalFocusableElements]`: Renders active modal dialogs (`open_db`, `create_doc`, `delete_doc`, `delete_col`, `clear_db`) with `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, unique `for`/`id` field associations, safe `mousedown` + `click` backdrop dismissal, guarded `Escape`/`Tab` focus trapping, and form validation; calls `../api.js`, `../state.js`, and `../router.js` directly while delegating database selection, path hydration, list refresh, toast notifications, and re-rendering via `ModalCallbacks`.

## Invariants
- `[editor.js:renderHybridEditor]`: Inside the inner `switchMode` handler, switching from Raw ProtoJSON mode back to Structured Tree mode re-validates `validateRawProtoJsonFields(session.rawText)` so invalid JSON text cannot corrupt the structured `DraftNode` tree, and switching from Structured to Raw is blocked when `draftNodesToFields` fails.
- `[editor.js:valueToDraftNode]` / `[editor.js:renderDraftNode]`: `__vector__` sentinel maps (verified via `[../values.js:isVectorMapValue]`) render as collapsed read-only `'vector'` rows (`vec` badge + `[../values.js:formatVectorSummary]` + remove `✕` button, without a type dropdown or nested tree) and pass their untouched `rawVectorValue` from `cleanDoc` through verbatim on save (preserving untouched `-0.0` coordinates and dirty state across Structured <-> Raw ProtoJSON mode switches via `cleanJson` / `rawBaselineText`).
- `[editor.js:computeChangedFieldMask]` / `[editor.js:recomputeDirty]`: In structured mode, diffs `cleanDoc.fields` against draft fields structurally via `[../values.js:firestoreValueEquals]` rather than `JSON.stringify` (avoiding false positives from map key ordering or `-0` normalization while keeping untouched vector fields out of `updateMask`); in raw mode, checks `session.rawText.trim() !== session.cleanJson.trim()`.
- `[editor.js:collectMapNodes]` / `[editor.js:renderDraftNode]`: Sibling field keys inside any `Document.fields` or `mapValue.fields` object must be non-empty and unique before saving or syncing to ProtoJSON (invoked via `draftNodesToFields`). Validation tracks `keyError` and `valueError` separately per node ID (`NodeValidationError`) so empty/duplicate key errors apply `.input-error` to `.field-key-input` while value errors apply `.input-error` to the value control without overwriting each other, and rejected `switchBytesMode("utf8")` conversions on non-UTF-8 bytes surface an inline `node.bytesModeError` without dirtying a clean session (cleared on edit, type change, mode switch, or revert).
- `[query.js:FILTER_OPERATORS]`: All 14 `StructuredQuery` operators supported by `crates/emulator-database/src/database/query/filter.rs` are exposed in the visual query builder, with `IN`, `ARRAY_CONTAINS_ANY`, and `NOT_IN` sharing the `kind: "array"` editor mode. Visual array parsing runs `[../values.js:findUnsafeUnquotedInteger]` before `JSON.parse`, runs `[../values.js:findNonFiniteNumber]` (preserving `"overflows IEEE-754 double"`), validates explicit ProtoJSON entries via `[../values.js:normalizeProtoValue]` (requiring string `"Infinity"`/`"-Infinity"`/`"NaN"` on explicit `doubleValue` objects and passing `inArray = f.op === "ARRAY_CONTAINS_ANY"` so `ARRAY_CONTAINS_ANY` disallows nested `arrayValue` objects while `IN`/`NOT_IN` permit single-level `arrayValue` objects), encodes non-`-0` `Number.isSafeInteger` shorthand items as `integerValue` strings, encodes `-0`, fractional numbers, and unsafe-integer floats as numeric `doubleValue`s, and rejects nested JS arrays (`Array.isArray(item)`).
- `[query.js:buildAggregationQueryFromVisual]` / `[query.js:renderQueryRunner]`: Enforces edition-aware aggregation limits (Standard `1..=5` vs. Enterprise `1..=64` when `{ enterprise: true }` / `enterprise: true`; `COUNT` clearing and disabling `fieldPath`; `SUM`/`AVG` requiring non-empty `fieldPath`; blank aliases omitted in emitted JSON with sequential `field_1`..`field_N` placeholders; explicit aliases rejecting `[../values.js:isReservedName]` on Standard only while allowing reserved `__...__` aliases on Enterprise, and rejecting `> 1500` UTF-8 bytes on both editions; prototype-safe `Set` uniqueness across effective aliases). Decouples untouched `limitText` (`"50"` <-> `""`) across `queryKind` toggles gated by `limitUserModified`, renders an inline `!` warning (`.query-limit-warning`) for non-empty aggregation limits, compiles valid non-pristine Visual state or passes pristine default Visual state through on `Visual -> Raw` while blocking invalid Visual clauses in `Visual` mode, swaps directly between `rawQueryText` and `rawAggregationText` on `queryKind` changes in Raw mode, renders aggregation `aggregateFields` losslessly via `Object.entries`/`Object.hasOwn`, `formatValuePreview`, `getValueType`, `VALUE_TYPES` labels (`"int64"`, `"double"`, `"null"`), and `.agg-provenance-note`, wires comboboxes with stable `row.id` keys when `suggestions` is provided and `mode === "visual"` (reconciling `renderedIds` unconditionally via `reconcileComboboxUi` with `renderedIds` empty outside `"visual"` mode), and applies non-clobbering filter auto-type detection (`applyFilterAutoType`) gated by `!f.valueTypeManuallySet && !f.valueUserEdited` (normalizing unedited `booleanValue` text to `"true"` on auto-type or array->scalar operator transitions and clearing unedited `"true"` when auto-typing away).
- `[combobox.js:renderCombobox]` / `[combobox.js:reconcileComboboxUi]`: Pure `lit-html` function templates with zero `HTMLElement` / `customElements` dependencies and per-member browser-API guards (`window`/`document`/`requestAnimationFrame`), maintaining strict `<ul role="listbox">` -> `<li role="option">` child purity, viewport-fixed positioning with `flipUp`, and capture-phase `scroll`/`resize` cleanup (`{ capture: true }`) on close/reconcile/clip.
- `[query-suggestions.js:runCachedFetch]` / `[query-suggestions.js:markSuggestionsStale]`: Uses standard Firestore v1 REST endpoints only (zero `/emulator/v1` introspection calls), deduplicates concurrent non-`force` loads, aborts prior key controllers on `force`, checks `!signal.aborted && reqEpoch === store.epoch` before cache mutations, clears `loading = false` silently on errors, uses prototype-safe `Map`s, and marks matching caches stale lazily on exact resource segment boundaries.
- `[contention.js:renderContention]` / `[contention.js:updateWaiterElapsedDom]`: `.wait-elapsed` spans are rendered empty by `lit-html` (no `ChildPart` comment anchors) and have their `textContent` owned solely by `updateWaiterElapsedDom` (callers must invoke it immediately after rendering and on waiter ticks, falling back to `data-wait-label` when `lastFetchedAtMs === null`). When `snapshot === null && !loading && error`, summary cards render `"—"` and `.contention-body` renders an explicit error + `Retry` control instead of zeroed cards or empty-state copy.

## Side Effects
- `explorer.js`, `editor.js`, `query.js`, and `contention.js`: Pure DOM template construction and in-memory `EditorSession` / `QueryRunnerState` / `ContentionState` usage (`updateWaiterElapsedDom` directly mutates `[data-wait-base-ms]` element text/attributes; `query.js` invokes `query-suggestions.js` loaders and `reconcileComboboxUi` when `suggestions` is provided); query execution and Explorer I/O delegate upward to callbacks in `[../app.js]`.
- `combobox.js`: Registers and cleans up `window` capture-phase `scroll` and `resize` listeners via `uiState.cleanup` and calls `scrollIntoView` inside `requestAnimationFrame`.
- `query-suggestions.js`: Issues `AbortSignal`-scoped standard Firestore v1 REST `fetch` calls via `[../api.js]` (`listCollectionIds`, `listDocuments`, `runQuery`) and caches results on `QuerySuggestionStore`.
- `modals.js`: Mutates `state.modal` / `state.segments` / `state.rootCollections` / `state.databases`, bumps/updates epochs, request sequences, and caches directly via `[../state.js]` (`bumpDbEpoch`, `bumpNavEpoch`, `deleteDocumentLevelCache`, `pruneCachesWithPrefix`, `clearActiveDatabaseState`), calls Firestore/Emulator APIs directly via `[../api.js]`, updates history directly via `[../router.js:syncBrowserUrl]`, and delegates database selection/hydration/list refresh/toast/rendering to `ModalCallbacks` in `[../app.js]`.
